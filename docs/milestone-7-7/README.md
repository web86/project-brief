# Milestone 7.7 — профессиональный компактный экспорт

Ветка `codex/milestone-7-7-document-export`, база Milestone 7.6 `7a5fdfab1c0230177bc2d22ddfef7b54c8fa5691`. Все примеры собственные, синтетические; данные Almariss и других клиентов не использовались. Push, merge и production deployment не выполнялись.

## Документ

Один шаблон для существующих настроек: компактная фирменная строка → заголовок и проект → сайт/дата → пронумерованные разделы и задачи → итоги → реквизиты. Без титульной страницы, карточек задач, фоновых плашек и повторяющегося слова «Описание». Результат и технические заметки имеют подпись в начале первого абзаца. Метаданные одной строкой после содержания, часы не дублируются в заголовке. Обычный приоритет сохраняется при включённом поле.

A4: поля 17 мм, PDF 9.25 pt / 1.23, DOCX 9.5 pt / 1.25; разделы 12.5 pt, задачи 10.25/10.5 pt, метаданные 8.25/8.5 pt. PDF использует прежний DejaVu и посимвольный CJK fallback; DOCX — Calibri с существующими встроенными китайскими шрифтами. Цвет применяется только к номерам разделов, с достаточной читаемостью на белом. Остальной текст тёмный/серый и подходит для чёрно-белой печати.

Короткие задачи удерживаются вместе; длинные задачи разбиваются по исходным абзацам. Короткие абзацы сохраняются целиком. Заголовки связаны с началом содержания средствами pdfmake/PHPWord; высота задач не фиксируется. Настройка начала каждого раздела с новой страницы сохранена. Реквизиты — две колонки без рамок, длинные значения переносятся, примечание занимает полную ширину. Footer содержит компанию/проект, разрешённое упоминание платформы и номер страницы.

## Итоги и данные

`status=approved` и `client_approved` — разные сущности. Прежний `approvedCount` считал формальное подтверждение клиентом, поэтому ноль при девяти задачах со статусом «Согласовано» был возможен. Теперь показатель явно назван «Согласовано клиентом», а при включённом статусе отдельно выводятся ненулевые «Согласовано по статусу», «Требуют уточнения», «Готово по статусу». Никакого изменения статусов или автоматического клиентского согласования нет.

В собственном примере `studio-ru`: 11 задач, согласовано по статусу 9, требуют уточнения 1, подтверждено клиентом 0, 20 ч для 10 из 11 задач, стоимость «Не рассчитана» для 0 из 11. Это намеренно воспроизводит проблему смысла показателей.

Все цены отсутствуют → «Не рассчитана». Явные нули → обычные 0 в валюте. Частичные цены → точная сумма известных значений и существующее примечание «Стоимость указана для X из N задач». Полное заполнение → обычная сумма без примечания. Денежная арифметика в целых minor units/десятичных строках сохранена. Все показатели считаются после существующего отбора all/approved/done; scope approved по-прежнему означает формальное подтверждение клиента.

PDF и DOCX получают один `ProjectExportData`: одинаковые флаги полей, метаданные, валюта, итоги и реквизиты. Приватные поля клиента и чужого workspace остаются исключены. При отключённых реквизитах их нет и в публичных данных PDF. Новых настроек и миграций нет.

## Изображения и совместимость

PNG готовится для области логотипа 86 × 28 pt с целевым 300 DPI, alpha сохраняется, увеличения маленьких изображений нет. Если уже нормализованный компактный PNG сжимается лучше уменьшенной версии, сохраняется меньший файл. Исходные огромные загрузки уже ограничены прежним pipeline 7.6 до 1024 px; upload/storage и email не переписываются.

Очищенный SVG из геометрических фигур используется напрямую в PDF без PNG-дубликата. SVG с текстом или префиксами пространств имён получает проверенный PNG fallback: pdfmake не предоставляет надёжного посимвольного fallback для смешанного SVG-текста. DOCX продолжает использовать PNG. Существующая строгая SVG-очистка сохранена.

Новый PDF adapter автоматически передаёт заголовок `X-ProjectBrief-Pdf-Renderer: 2`. Без него API возвращает PNG, чтобы старый закешированный worker 7.6 не потерял логотип при обновлении. Это внутреннее согласование возможностей, пользовательских переключателей нет. Версия JSON-схемы остаётся совместимой, добавлены только необязательные ключи.
