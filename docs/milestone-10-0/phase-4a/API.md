# Resource preparation API

Prefixes: owner `/api/admin/resource-selection`; primary `/api/platform/workspaces/{workspaceUuid}/resource-selection`. Existing session authentication, workspace scope, strong/fresh account-security proof, CSRF for mutations and throttles apply. Platform additionally requires verified email/no recovery window and current primary authority. Domain authorization repeats under workspace mutex; ordinary platform_admin is denied. Responses are no-store/no-referrer. Platform resource options use safe IDs, never project titles, emails, messages, task content or credentials; owner may see authorized project/member labels.

| Method/suffix             | Contract                                                                                                                                                                         |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET `/`                   | Current options, canonical usage, subscriptionRevision, fingerprint, previewOnly=true/executorAvailable=false                                                                    |
| GET `/versions?page=N`    | Published assignable free/paid versions, 100/page; owner public only; compatibility excluded                                                                                     |
| POST `/previews`          | `targetVersionId`, `selection` with exact arrays projects/developers/clients/agents/invitations; If-Match `"revision:N"` subscription revision; Idempotency-Key 1–128 safe ASCII |
| GET `/previews/{uuid}`    | Reopens only same actor/workspace/context. Recomputes fingerprints, target, registry, settings, authority, expiry and selection; never a stored permit                           |
| GET `/accounting-review`  | Bounded safe evidence indicators: verified-source count, contact/email fallback presence, contradiction; opaque input HMAC and observation revision                              |
| POST `/accounting-review` | `clientId`, action confirm/separate, `inputHash`, reason code, literal confirmation `ACCOUNTING ONLY`; If-Match observation revision and Idempotency-Key                         |

Each selection array is unique, bounded to 250 IDs; unknown/cross-workspace IDs rejected. Owners are mandatory. Client IDs denote distinct accounting identities and must participate in selected projects; exact project-client UUIDs are also frozen. Developer count is union(active selected user IDs, valid selected pending invite user/email identities), not array length. Shared credentials never collapse distinct agents. Target uses published typed values and simulated extra seats zero. Above-capacity or incomplete evidence is needs_review, not active suspension.

Preview is metadata created with mandatory audit. Same intent/key returns the same preview **after fresh validation**; changed body conflicts. Expired/stale/authority drift returns 409; lost authorization 403; another actor/workspace preview 404; malformed selections/evidence 422; missing If-Match 428. `current_snapshot_refresh_required` 409 asks for a new request when MariaDB cannot refresh an older snapshot. UI offers recalculation; never reuses a stale selection silently.

Review writes only accounting identity FK/observation/alias quarantine, inventory checkpoint metadata and audit in one transaction. It does not merge users, change SSO bindings, email accounts, project access tokens or grants. Proven source contradictions, multiple anchors or a requested verified-subject split stay needs_review (422). Contact/email-only separation creates a new isolated accounting UUID; verified-source aliases of other participations remain intact. Same evidence receipt survives reconciliation, but changed provenance invalidates it. No generic Merge action.

No `/apply`, `/downgrade`, `/suspend`, commercial confirmation endpoint, background executor or activation feature flag is added. Resource selection is not a reservation. Safe existing cancellation/revoke/history/export/recovery/basic login/MFA/Magic Link continue to use existing authorization.
