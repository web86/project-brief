## Update under maintenance

1. Verify ZIP SHA-256, release.json source commit/version/UTC/PHP target and checksums.txt against ARTIFACTS.md. Back up a consistent database/private uploads and matching public/private code/vendor. Preserve installed `.env`, APP_KEY, storage, sessions, paths and permissions. Private application stays outside web root. No test/demo credentials may be installed.
2. Enter maintenance with the old runtime (`php artisan down`), pause existing cron/processors using DEPLOY-JINO.md. Replace matching public and private/project-brief-app together. Restore retained `.env` and persistent storage. Keep APP_ENV=production, APP_DEBUG=false, secure HTTPS cookies and approved origin/proxy configuration. Keep REGISTRATION_ENABLED=false and TRIAL_ACTIVATION_ENABLED=false. Unset provider credentials are valid and require no setup.
3. In the new PHP 8.4 private runtime run `php artisan optimize:clear`, inspect `php artisan migrate:status`, then `php artisan migrate --force --no-interaction`. From v0.9.14 only the new onboarding migration is pending. It adds password_login_enabled=true for legacy users and new onboarding/attempt tables, without changing their email verification, memberships or sessions. It is reentrant for completed structure/index/foreign-key repair. If upgrading an earlier base, follow its existing runbook/prerequisites first. Never run migrate:fresh, migrate:rollback, demo reset, a demo seeder, or automatic plan publication.
4. Run `php artisan optimize`, inspect health, then `php artisan up` and resume existing processors. Verify actual owner login/MFA/passkey/recovery and invited developer/client/SSO access. Existing unverified owners must retain their prior policy. Verify exports, private files, API/agent/team privacy, custom branding and agreements. `/demo` and `/api/demo/status` remain404 on production. Static Demo is a separate artifact and origin.

A POST signup must fail403 even if REGISTRATION_ENABLED is accidentally true; no new User/workspace/Trial should appear. Unconfigured providers remain unavailable. Primary PlanAuthority can inspect `/platform/plans/registration` with its existing strong/fresh requirements; secondary administrators cannot see diagnostics. There is no activation button.
6. Optional future provider setup uses OAUTH-SETUP.md, exact canonical HTTPS callbacks and log redaction of callback query arguments. Do not enable public commercial access by setting env flags. Do not seed/publish policies, run inventory, assign authority or modify subscriptions just because this release was installed.

Existing scheduled processors continue under their previous contracts. The new expired-attempt pruning command is optional and unscheduled; no Redis, worker or additional mandatory cron is introduced. Durable Trial subjects have no automatic deletion. An approved retention horizon and key-rotation strategy are prerequisites for future commercial rollout.

## Rollback

Enter maintenance and pause processors. Restore matching v0.9.14 public/private code/vendor, retaining the current database schema, APP_KEY, env, storage and uploads. Clear/rebuild caches with the restored runtime, verify existing access and then resume. Do not drop onboarding tables, reset verification or aliases, run migration down, or overwrite newer data with an old DB backup.

Production registration is hard off, so a normal upgrade should create no new self-service users. **Before restoring old code, inspect whether local/staging/operator testing created new onboarding accounts in that installation.** Old code does not enforce the new onboarding gate. If such accounts exist, keep maintenance enabled and require a reviewed quarantine/forward-fix plan; do not expose a prepared owner workspace through the older runtime. Retain identity/claim/audit history. Provider-only accounts may also lack a usable old-runtime primary method. Rehearse this on a restored isolated copy before any future public rollout.

The existing v3 Static Demo ZIP is reused unchanged, separately from production PHP. Do not upload production runtime into its origin or its snapshots over the live application. Honor its existing cache/hashed-asset hosting instructions.
