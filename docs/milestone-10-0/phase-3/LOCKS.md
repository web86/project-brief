# Phase 3 — lock-order review

Проверены текущие source writers перед подключением accounting; это не заявление о готовности Phase 4 enforcement.

| Путь                                                           | Phase 3                                                                                                                                                                                                                                                                                           |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CurrentWorkspace::resolve(lock=true)                           | Сначала untrusted read-only lookup выбранного workspace, затем SELECT FOR UPDATE workspace mutex, затем current locking membership read; stale membership повторно отклоняется. Убрана membership → workspace inversion                                                                           |
| Developer invitations / ProjectTeam / WorkspaceAdministrator   | Existing transactions workspace → manager/member/invitation. Reservation sync добавлен после existing writes под тем же mutex. issue имеет собственную transaction/mutex для прямого caller; accept membership+consumed hold в одной transaction                                                  |
| AccountProfile email update                                    | Существующий account writer не получает новый workspace lock после user lock. Usage rematches current invitations/users; explicit inventory refresh обновляет stored reservation hints. Перед enforcement нужен cross-workspace email-change protocol                                             |
| ProjectCreation / project restore/trash / client participation | Existing workspace-first paths сохранены; тарифные guards не добавлены. Базовые statuses и client active flags backfill не меняет                                                                                                                                                                 |
| AgentController / assignments / AgentCredentials               | Existing workspace mutex/current credentials/generation/scopes сохранены; identity counter не читает private runs и не меняет assignments                                                                                                                                                         |
| IntegrationWrites                                              | Existing workspace first + scope/grant/object recheck до replay сохранены; тарифный permit или replay bypass не добавлен                                                                                                                                                                          |
| WebhookProcessor                                               | Теперь workspace lock для **всех** endpoint kinds, затем existing lease → endpoint → delivery protocol. Independent endpoints больше не пропускают workspace. Bounded network-under-lock protocol/SSRF/TLS/HMAC/retries сохранены                                                                 |
| Inventory                                                      | Bootstrap global settings/catalog/cohort transaction заканчивается до workspace processing. Workspace → item/subscription → project-client/observation/alias/invitation/reservation. Global catalog/authority locks не берутся под workspace; immutable version pointer читается без catalog lock |
| Impact / platform UI                                           | Existing authority/user security transaction; provider не берёт workspace/child locks и не мутирует business state. Это согласованный read snapshot, не future allocation permit                                                                                                                  |

InnoDB current locking reads защищают writers/backfill. Preview может дрейфовать; asOf/hash не разрешает apply. До Phase 4 нужны current-read counters в каждой execution transaction, epoch/cycle high-watermarks, account email/ownership handling и полная future guard matrix. Нет глобального lock на все workspace.

MariaDB tests используют независимые процессы/barrier для двух backfill workers, duplicate invitations и project/client drift. Повтор после committed chunk продолжает cursor. Audit failure откатывает chunk. DDL восстановление проверяется после удаления отдельного index. Future capacity-denial/expiry/execution races не выдаются за пройденные Phase 3 тесты.

Workspace membership resolution не вызывает SQLite dummy UPDATE из write-only IntegrationWrites adapter: read-only demo GET внутри тестовой outer transaction остаётся SELECT-only. MariaDB workspace row lock сохраняется.
