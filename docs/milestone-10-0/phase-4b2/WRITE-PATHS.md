# Аудит путей записи Phase 4B.2

| Путь                                                                                                                                     | Общая проверка и граница записи                                                                                                                                                                                                                               |
| ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST /api/admin/projects, POST /api/v1/projects                                                                                          | ProjectCreation блокирует workspace и проверяет effective projects и initial client в транзакции до публикации событий.                                                                                                                                       |
| POST /api/v1/projects/provision, POST /api/v1/project-requests/{uuid}/approve, POST /api/admin/project-requests/{uuid}/approve           | ProjectProvisioning использует ProjectCreation. Клиентское участие создаётся отдельной записью, поэтому после неё добавлена проверка clients.max и учёт identity до записи результата provisioning.                                                           |
| PATCH /api/admin/projects/{project}, POST /api/admin/projects/{projectUuid}/restore                                                      | Workspace и проект блокируются перед сменой статуса или restore. Effective projects и clients проверяются после записи внутри той же транзакции.                                                                                                              |
| POST/PATCH /api/admin/projects/{project}/clients, выдача приглашения и Magic Link                                                        | Создание и активация проверяют effective clients. Выдача ссылки требует доступного project-client participation. Клиентские SSO handoffs дополнительно проверяют execution epoch.                                                                             |
| POST /api/admin/projects/{project}/team/invitations, POST /team/members                                                                  | Workspace mutex. Оба пути теперь проверяют writable project, включая ветку добавления уже существующего разработчика по email. Присоединение сохраняет текущий workspace membership и не снимает его hold.                                                    |
| POST /api/admin/administrators/invitations, POST /invitations/{uuid}/link, POST /invitations/{uuid}/resend, POST /api/invitations/accept | DeveloperInvitations резервирует и проверяет union seats под workspace mutex. Accept проверяет срок, identity, назначенные проекты и reservation receipt текущего cycle.                                                                                      |
| PATCH /api/admin/administrators/invitations/{uuid}, PATCH /api/admin/administrators/members/{id}                                         | Редактирование приглашения не выдаёт новый token и не меняет email. Accept перепроверяет выбранные проекты. Активация membership проверяет seats. Для новой связи с проектом добавлена проверка held под mutex.                                               |
| POST/PATCH /api/admin/integrations/agents, POST /api/admin/projects/{project}/team/agents/{uuid}, POST /api/admin/tasks/{task}/agents    | Workspace mutex, current agent/plan check и project participation. Создание и активация проверяют agents.active.max. Присоединение и task assignment сохраняют существующие grants, а запуск проверяет epoch.                                                 |
| POST /api/admin/resource-selection/previews/{uuid}/apply-basic или restore-paid, POST /api/admin/resource-selection/rearm                | Owner и fresh MFA. Workspace mutex, привязанный к ревизии frozen preview и повторная сверка capacity и identity. Rearm записывает новую epoch после отдельного подтверждения.                                                                                 |
| app:create-admin, внутренний OwnerProvisioning                                                                                           | Создаётся первый владелец нового workspace. Legacy recovery использует workspace без участников и не является путём добавления места в действующий коммерческий workspace.                                                                                    |
| plans:inventory, legacy migrations, demo:reset                                                                                           | Инвентаризация пишет accounting и Compatibility pins. Исторический backfill проверяется на старой схеме. Demo seeding относится к изолированной demo-конфигурации.                                                                                            |
| plans:reconcile-subscriptions, integrations:webhooks, provisioning delivery, projects:feedback-mail                                      | Reconciliation и processor меняют состояние выполнения, а не выделяют seats. Provisioning delivery повторно проверяет suspension перед выдачей и отправкой ссылки. Для остальных фоновых сценариев требуется отдельное подтверждение покрытия перед выпуском. |

Матрица фиксирует найденные точки входа и результаты чтения кода. Она не заменяет полный regression, adversarial race tests и проверку извлечённого ZIP.
