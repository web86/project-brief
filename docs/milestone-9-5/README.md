# Milestone 9.5 — Agreements, Team Management, Invitation UX & Private Team Chat

База — v0.9.4; ветка `codex/milestone-9-5-team-improvements`. Существующая Laravel/Vue архитектура, локализация, MFA, SSO и брендирование сохранены. Новые зависимости не добавлены. Push и deployment не выполняются.

## Изменения

- Соглашения: четыре полных примера по девяти разделам, RU default/enabled у нового workspace, остальные переводы подготовлены и выключены. Требование принятия и публикация выключены. Текст существующих workspace не заменяется. Кнопка заполнения работает только по действию владельца с подтверждением замены непустого текста.
- Черновик хранит enabledLocales/defaultLocale; default обязан быть включён, хотя бы один язык остаётся включён. Выключенный перевод редактируется и сохраняется. Публикация фиксирует конфигурацию и новый immutable UUID-снимок; фактические язык, дата и UUID принятия остаются на сервере. Смена языка интерфейса не создаёт повторного принятия. Старые опубликованные документы без locale-полей сохраняют четыре языка. Архив текста начинается с текущей публикации при миграции v0.9.5; исторические факты принятия не удаляются, отсутствующие ранее снимки текста не выдумываются.
- Карточки команды: имя/email/аватар, назначение, роль и TOTP/Passkey. Только удаление назначения с подтверждением. Карточка владельца отделена от заголовка и формы приглашения. Не показывается выдуманный online.
- `workspace_members.is_project_superadmin` и одноимённый флаг приглашения по умолчанию false. Только владелец изменяет глобальное право. Явное назначение обязательно для каждого проекта. Суперадминистратор управляет проектом/клиентами/командой/настройками/уведомлениями и мягким удалением/восстановлением; создание проектов, глобальные настройки и окончательное удаление не предоставляются. Старый can_create_projects больше не выдаёт создание. Обычные функции задач и ранее разрешённые structure/export остаются; advanced management и корзина недоступны обычному администратору и проверяются API.
- Приглашения команды ограничены текущим проектом; нельзя передать глобальные права или чужие project IDs. Приём повторно проверяет полномочия и назначение пригласившего. Приглашение перестаёт работать после их отзыва.
- Бренд приглашения определяется по проверенному token hash/server session. F5 после удаления raw token из адреса работает; MFA-ротация сессии сохраняет подтверждённый контекст. Публичный branding endpoint не принимает workspace ID как основание доступа. Невалидный/отозванный контекст не подставляет другой бренд. Первый экран безопасности компактный, форма Passkey раскрывается по действию, обязательность MFA и допустимость пропуска проверяет существующая политика.
- Внутренний чат заменяет общую вкладку у команды; у клиента остаются обсуждения задач. По уточнению пользователя существующие общие сообщения разработки переводятся в приватный канал. Таблицы comments/attachments/comment_reads и существующий Live Sync переиспользованы. Дополнительного polling нет. Текст, файлы, unread, уведомления и прямые API проверяют назначение и workspace. Клиентские API/экспорт/webhooks/integrations исключают приватные сообщения. Повтор POST с submissionId не дублирует сообщения/файлы.

Шаблоны — редактируемые примеры, не автоматически применимое право. Упоминания GDPR/KVKK сопровождаются «когда применимо». При подготовке использованы первичные сведения [GDPR, статьи 5 и 32](https://eur-lex.europa.eu/eli/reg/2016/679/oj) и [KVKK, статья 12](https://www.kvkk.gov.tr/Icerik/6649/Personal-Data-Protection-Law); тексты написаны самостоятельно и смыслово согласованы на четырёх языках.
