# Milestone 4.1.1 — ZvenoAI Integration & Model Benchmark

## Результат

Поддержка ZvenoAI добавлена в существующий Laravel `AiTaskAssistant`;
Groq сохранён как альтернативный и остаётся провайдером по умолчанию.
Интеграционные тесты двух провайдеров проходят на одинаковом контракте.
Реальные запросы к ZvenoAI выполнены с предоставленным ключом и только
синтетическими данными. **Успешная генерация через бесплатные маршруты не
подтверждена, победитель не выбран.**

Причина: все 9 запросов с `response_format: json_schema`, `strict: true` вернули
HTTP 400. Дополнительная диагностика Nemotron получила конкретный отказ
`no provider supporting response format`. Последующий текстовый диагностический
запрос получил HTTP 429 с сообщением об исчерпанной дневной квоте бесплатных моделей.
Вызовы остановлены без автоматического fallback, платных моделей и повторных попыток.

Это не положительный benchmark качества и не свидетельство неработоспособности
самих моделей вообще: зафиксирован отказ маршрутов при текущих параметрах/аккаунте.
Скорость отказа нельзя выдавать за скорость генерации. До повторного успешного
строгого теста ни одна из трёх бесплатных моделей не рекомендуется для production
AI Task Assistant. Совместимость Groq проверена с `Http::fake()`; live Groq в этой
итерации не вызывался.

## Методика

Команда `php artisan ai:benchmark` использует тот же сервис, system prompt,
JSON Schema и валидатор, что HTTP endpoints формы. База данных, проекты, задачи,
клиенты, файлы, комментарии и private notes командой не читаются.

Три встроенных сценария из задания:

1. `simple`: «Хочу, чтобы фотографии товаров были крупнее и их можно было листать на телефоне».
2. `vague`: «Сайт работает медленно, особенно каталог. Нужно сделать быстрее».
3. `multiple`: «Нужно сделать личный кабинет, историю заказов, онлайн-оплату и уведомления о доставке».

Одинаковые настройки трёх моделей: `max_tokens=6000`, `stream=false`,
`reasoning.effort=low`, `reasoning.exclude=true`, строгая схема Milestone 4.1,
connect timeout 5 секунд, request timeout 25 секунд. Задержка между POST — 10 секунд;
генерации выполнялись последовательно. Производственное поведение без fallback сохранено.

Основной batch: 19:33:47–19:35:12 UTC 19.10.2026. Начальная версия команды выполнила
все 9 сценариев. После анализа ошибок команда улучшена: HTTP 400 пропускает оставшиеся
сценарии этой модели; HTTP 401/402/403/429 останавливает весь batch.
Повторный одиночный strict-запрос был диагностикой причины отказа, а не попыткой
улучшить статистику. Всего **11 авторизованных POST**: 9 основных + 1 strict diagnostic

- 1 text diagnostic. Автоматических повторов не было. В момент 429 оставшиеся
  8 текстовых сценариев не запускались.

Более быстрый отказ Dots не означает, что модель быстрее или лучше пишет ТЗ.
Возможности сохранять обязательные поля, пустые массивы, отсутствие лишних ключей
и завершение JSON в пределах токенов **live не проверены**, потому что генерация
не состоялась. Эти ветви проверены только через `Http::fake()`, что подтверждает
валидатор приложения, а не возможности реального маршрута.

Дополнительные наблюдения:

| Запрос            | Режим                                                    | HTTP | Время    | Фактический ответ                                                                         |
| ----------------- | -------------------------------------------------------- | ---- | -------- | ----------------------------------------------------------------------------------------- |
| Nemotron / simple | `json_schema`, strict                                    | 400  | 282.8 мс | `model nvidia/nemotron-3-super-120b-a12b:free has no provider supporting response format` |
| Nemotron / simple | обычный текст + просьба вернуть JSON, только диагностика | 429  | 382.5 мс | «Дневной лимит бесплатных моделей платформы исчерпан, сброс в 03:00 МСК»                  |

На основании сообщения 429 нельзя установить точное число запросов дневной квоты:
предыдущее использование аккаунта неизвестно. `usage` не возвращён — количество
токенов неизвестно, не следует подставлять 0. JSON mode отдельно не запускался после 429. Production не использует ни текстовый, ни JSON object режим.

[Машиночитаемые наблюдения](milestone-4-1-1-results.json) содержат исходные метаданные
трёх запусков без ключа. В начальной версии поля проверки JSON/схемы имели `false`
при отсутствии ответа; в новой команде такой случай обозначается `null` / `n/a`,
чтобы отличать отсутствие генерации от полученного невалидного JSON.

## Реализация и безопасность

- `AI_PROVIDER=groq|zveno`; прежние `GROQ_API_KEY` / `GROQ_MODEL` продолжают работать.
  Для Zveno: `ZVENO_API_KEY` / `AI_MODEL`. URL фиксированы в сервисе.
- Production `suggest()` всегда применяет исходную строгую JSON Schema и тот же
  серверный валидатор. FormRequest, проектные middleware и Vue-применение не изменены.
- Минутная и суточная квоты workspace общие для обоих провайдеров; смена провайдера
  их не сбрасывает. Неуспешный provider POST расходует попытку.
- Команда намеренно не использует существующий workspace: только её фиксированные
  синтетические сценарии, ограниченный список бесплатных моделей и до 9 POST.
  HTTP endpoint не позволяет получить доступ к этому обходу workspace-квоты.
- Production не сохраняет запросы/ответы в БД или логи. Ограниченные диагностики
  ошибок и синтетические предложения CLI могут сохраняться только в явно указанный
  report-файл; известные API-ключи редактируются из текста ошибки.
- Frontend не получает ключ. Изменены только RU/EN строки: уведомление называет
  внешних провайдеров Groq/ZvenoAI и предупреждает об обучении бесплатных моделей.
  Ручное редактирование, применение без сохранения и защита черновика сохранены.
- Ключ из задания записан только в игнорируемый `api/.env` с правами 0600. Значение
  не скопировано в примеры, команды, report-файлы или Git. Пользователь планирует
  заменить тестовый ключ после завершения.

## Jino и воспроизведение

Измерения выполнены с локального Mac. Доступ к каталогу HTTP 200 с Jino, ранее
проверенный пользователем, не подтверждает авторизованный успешный POST с этого
хостинга. **POST с Jino в этой итерации не выполнялся**: deployment и удалённые
изменения не разрешены. Скорость генерации и её совместимость с PHP/web timeout
Jino неизвестны. Увеличивать тайм-аут по времени быстрых HTTP-отказов нет оснований.

На локальном Mac PHP указывал отсутствующий CA bundle; это приводило к cURL errno 77
до сетевого запроса. Для benchmark был указан существующий CA bundle через `php -d`.
TLS-проверка не отключалась, глобальная PHP-конфигурация не менялась.

Настройте только backend `api/.env` (ключ не передавайте через CLI):

```dotenv
AI_ENABLED=true
AI_PROVIDER=zveno
ZVENO_API_KEY=your-server-side-key
AI_MODEL=nvidia/nemotron-3-super-120b-a12b:free
```

После изменения закэшированной конфигурации выполните `php artisan config:clear`.
План без сети: `cd api && php artisan ai:benchmark`.
После восстановления квоты и подтверждения маршрута начните с одного строгого запроса:

```sh
php artisan ai:benchmark --live \
  --model=nvidia/nemotron-3-super-120b-a12b:free --scenario=simple \
  --output=/tmp/zveno-strict-single.json
```

Для проблемного локального PHP добавьте перед `artisan`:
`-d openssl.cafile=/usr/local/etc/ca-certificates/cert.pem -d curl.cainfo=/usr/local/etc/ca-certificates/cert.pem`.
Этот путь специфичен для Mac и не должен переноситься на Jino.

Полный строгий запуск: `php artisan ai:benchmark --live --output=/tmp/zveno-strict.json`.
Выборки `--model` и `--scenario` повторяемы; `--delay=10..60` задаёт pacing.
Файл должен отсутствовать, директория — существовать.
`--format=json_object|text` — только явно запрошенная CLI-диагностика, не production fallback.
Команда возвращает ненулевой exit code при ошибках/пропусках и не сообщает об успехе
benchmark без принятых ответов. После восстановления маршрутов и квоты проверку
строгого POST с Jino надо выполнить отдельно.
