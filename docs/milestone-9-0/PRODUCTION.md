# Project Brief 0.9.0 — Jino deployment и rollback

Инструкции подготовлены; действий на Jino не выполнялось. Нужны отдельное разрешение на deployment и доступ оператора. Локальные Docker-тесты PHP 8.4/MariaDB не доказывают состояние Jino/FPM, SMTP, внешних интеграций или реальных webhook-получателей.

1. Проверить текущий commit/release, PHP 8.4/extensions и MariaDB, доступ к SSH/CLI и резервным копиям. Сохранить текущий полный runtime, `.env`, `APP_KEY`, storage/uploads и согласованный backup БД. APP_KEY, origin/RP ID, cookie domain/HTTPS и existing cron не менять.
2. Сверить SHA-256/размер ZIP с RELEASE-ARTIFACT.json и `unzip -t`. Разложить `public/` и `private/project-brief-app/` по существующей схеме DEPLOY-JINO. Не загружать исходные tests/artifacts/node_modules/.git.
3. Перед переключением runtime убедиться, что дополнительное короткое DB-соединение на API worker укладывается в Jino max_connections. Проверить поддержку SET SESSION innodb_lock_wait_timeout=1 для того же DB user. На первом rollout допустимо задать `PLATFORM_API_METRICS_ENABLED=false` и включить после измерения. Аудит является обязательным для платформенных операций, а метрики — необязательными.
4. В private application выполнить обычные `php artisan down`, `php artisan migrate --force --no-interaction`, `php artisan optimize:clear`, затем обычную подготовку cache проекта и `php artisan up`. Единственная новая миграция `2026_10_29_211509_add_platform_administration` добавляет default-false users.platform_admin, две компактные таблицы и три индекса existing webhook created_at. Создание индексов на большой history может занять время/удерживать DDL locks: заранее измерить на копии БД и выбрать окно обслуживания. Никто не получает полномочия автоматически.
5. Найти ID существующей доверенной учётной записи. Она должна завершить TOTP enrollment и сохранить recovery codes через текущую авторизацию. В доверенной интерактивной SSH-сессии выполнить `php artisan platform:admin USER_ID`; независимо проверить личность, ввести `GRANT PLATFORM ADMIN USER_ID`. Не передавать email/password/recovery codes в shell history. Все её старые сессии и proof отзываются. Новый вход использует существующие `/admin/login` и MFA; затем `/platform`.
6. Проверить guest/ordinary owner => 401/403 для direct platform API; platform admin => доступ только после MFA/step-up. Проверить общую категорию invalid-token API, реальные разрешённые integration requests и hour bucket/source/token ID; workspace remains isolated, секретов/содержимого проектов в диагностике нет. Проверить текущий webhook worker и read-only statistics, audit, UI RU/EN/TR/ZH-CN, мобильную версию и Light/Dark.
7. Сравнить FPM latency/worker occupancy, API error/429 rate, DB connections и время UPSERT с baseline на Jino. Проверить отсутствие долгих lock waits. Нельзя переносить численные локальные benchmark results на Jino. При ухудшении отключить только optional metrics через `.env`, выполнить `php artisan config:clear`/штатный config cache, повторить проверку. Нового cron нет.

Отзыв полномочия: в доверенной интерактивной SSH-сессии `php artisan platform:admin USER_ID --revoke`, фраза `REVOKE PLATFORM ADMIN USER_ID`. Сессии/challenge отзываются, событие сохраняется в audit. При потере факторов используется существующая `account:recover-security EMAIL` после независимой проверки личности; платформа останется недоступна до нового enrollment и MFA.

При application rollback остановить запись/выполнить maintenance, вернуть проверенный runtime/public предыдущего 0.8.4, сохранить `.env`/APP_KEY/storage и additive schema. Выполнить `php artisan optimize:clear`, штатные cache-команды старого релиза и вывести из maintenance. **Не запускать migrate:rollback и не удалять users.platform_admin/platform_audit/api_usage_hours.** Старый runtime игнорирует эти данные; platform-only account без membership в старом runtime войти не сможет, обычные workspace ACL останутся прежними. Таблицы аудита и назначения должны пережить откат приложения. Восстановление всей БД — отдельный согласованный disaster recovery с учётом новых бизнес-записей; оно не является обычным rollback.
