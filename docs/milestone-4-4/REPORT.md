**Milestone 4.4 — рабочее пространство детальной страницы идеи**

Ветка: `codex/milestone-4-4-task-workspace`. Основа: Milestone 4.3, коммит `7b70754`. Изменения касаются frontend; backend, схема БД и зависимости не менялись. Миграция для Milestone 4.4 не нужна.

Реализовано:

1. Левая навигация «Задачи проекта» для обеих ролей. Разделы раскрываются независимо, раздел текущей задачи открывается автоматически, текущая задача выделена. На desktop панель скрывается с расширением основного содержимого; предпочтение сохраняется в localStorage. На mobile тот же экземпляр навигации переносится в нативную выдвижную панель через Teleport. Список берётся из существующего Pinia store текущего проекта.
2. На детальных страницах администратора прежний глобальный левый сайдбар заменён закрытой по умолчанию правой панелью поверх содержимого. В ней общая навигация проекта, бейдж обсуждений и компактный блок рабочей области: все проекты, выбор workspace, создание проекта, раскрываемый список проектов с прежними бейджами, данные аккаунта и выход. Компонент `AdminSidebar` переиспользуется в компактном режиме. На остальных страницах сохраняется прежняя оболочка; горизонтальное меню проекта осталось на месте.
3. Возврат к проекту перенесён в sticky-шапку. Имя пользователя убрано из неё, настройки темы/языка и Push сохранены. У администратора справа отдельная кнопка управления проектом. На mobile подпись возврата сокращается до «Проект» / «Project», доступное имя остаётся полным.
4. Над заголовком располагается строка раздела/расположения и важности, статус выровнен вправо и корректно переносится на узких экранах. Номер задачи находится в заголовке, выделен менее заметным акцентным цветом. Существующая иерархическая нумерация `#1.1` сохранена.
5. Существующий `DeveloperNotes` стал сворачиваемым и по умолчанию закрыт. Textarea остаётся смонтированной: сворачивание не теряет текст. При изменении заметок, часов или стоимости видимые предупреждение и кнопка сохранения находятся вне сворачиваемого содержимого; чистая карточка не показывает неактивную кнопку. Явное сохранение, Ctrl/Cmd+S, beforeunload и подтверждение ухода работают через прежние механизмы.
6. У администратора комментарии находятся непосредственно под заметками, история — в правой колонке под управлением задачей. На mobile блоки выстраиваются в одну колонку. Клиент сохраняет удобный доступ к комментариям, его история дополнительно фильтрует приватные события. Каждый компонент комментариев, истории и редактора присутствует в единственном экземпляре.
7. При переходах между уже загруженными задачами одного проекта переиспользуется разрешённый текущий snapshot проекта; повторных GET проекта/списка задач и лишних POST общего прочтения нет. Для другого проекта, неизвестной задачи, смены роли или потерянной сессии действуют обычная загрузка и проверки доступа. Возврат на страницу проекта и reload обновляют данные.
8. Обе мобильные панели взаимоисключающие. Нативные dialog обеспечивают модальность и удержание фокуса; работают Escape, закрытие по фону/кнопке и возврат фокуса. Принятый переход закрывает панели до ожидания данных, чтобы нативный верхний слой не оставлял прежние элементы активными. Отменённый переход с черновиком сохраняет редактор. Для правой панели есть анимация 160 мс и режим reduced motion.

Новых маршрутов или UI-библиотек нет. Общие ссылки проекта вынесены в `ProjectNavigation`; состояние представления — в небольшой `taskWorkspace` store и очищается при смене личности/рабочего пространства. Существующие комментарии, вложения, статусы, согласование и уведомления используют прежние компоненты и API.

Новые тесты проверяют обе роли, текущий проект и отказ от переиспользования чужого snapshot, автооткрытие разделов, ручное управление аккордеоном, сохранение предпочтения скрытия, заблокированный localStorage, отсутствие повторных загрузок, порядок блоков, приватность истории, сохранение черновика при сворачивании и отказе от перехода, повтор сохранения после HTTP 503, отправку комментария без приватных полей, фокус/клавиатуру/фон панелей, их взаимоисключение и закрытие до медленного перехода. В браузере дополнительно проверены sticky-шапка, перенос длинного заголовка, полная ширина блоков клиента, отступы мобильного подвала, resize 1440 → 390 → 1024 без дублирования DOM/запросов и обычная/reduced-motion анимация.

При визуальной проверке исправлен конфликт специфичности CSS, оставлявший у мобильного клиента узкую колонку деталей. Теперь браузерный тест проверяет не только отсутствие горизонтальной прокрутки, но и ширину содержимого, а также вертикальный порядок комментариев. Проверены 1440, 1024, 390 и 320 px, RU/EN, light/dark/system. Скриншоты панелей снимаются в viewport после завершения анимации, страницы — целиком.

```sh

```

Прежние сценарии Milestone 4.3 адаптированы к перемещению меню в правую панель. Для регрессионного прогона их снимки сохранялись во временную папку через `MILESTONE43_OUTPUT_DIR`; старые изображения Milestone 4.3 не перезаписывались.

Ограничения проверки: Chromium с эмуляцией мобильного viewport/touch, тестовый API в браузере и отдельные backend feature-тесты на SQLite. Физические устройства, Safari/iOS, production-БД и реальная доставка SMTP/Push не использовались. Список задач не обновляется в реальном времени: как и прежде, актуализируется при обычной загрузке проекта или reload. Постоянного хранения текста новых типов черновиков не добавлялось; существующие механизмы сохранены.

Изначальные незакоммиченные `.gitignore`, `README.md`, `package.json`, материалы публичного preview и прежние отчёты сохранены вне коммита Milestone 4.4. Push, deployment, сборка нового release ZIP и публикация GitHub Release в рамках этого этапа не выполнялись.
