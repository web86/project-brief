# Milestone 4.5.1 — двусторонний Telegram Bridge

Реализовано локально от `b1b0e73` в ветке
`codex/milestone-4-5-1-bidirectional-telegram-bridge`.
Ручное обновление: [PRODUCTION.md](PRODUCTION.md).
Машиночитаемые проверки: [checks.json](checks.json).

## Результат

- Deno принимает `POST /telegram/webhook`, проверяет Telegram secret и размер
  update (16 КБ), пересылает исходное тело на настроенный серверный HTTPS callback.
  Разрешён только `https://brief.web86.site/api/telegram/webhook`.
- Три роли секретов разделены. Telegram header не пересылается в Laravel;
  вместо него передаётся `X-Telegram-Forward-Secret`. Новый forward secret
  должен отличаться от webhook и bridge secrets. Bot token в Laravel не нужен.
- Laravel явно выбирает `TELEGRAM_WEBHOOK_TRANSPORT=deno|direct`; авторизация
  другого режима не является fallback. Прежний stateless-маршрут сохраняет
  CSRF/session-изоляцию, собственный rate limiter и проверку размера.
- Deno ждёт 2xx + `ok:true` Laravel; timeout — 8 секунд, включая тело ответа,
  без redirect и локальных повторов. Laravel 429/503 → Deno 503, сетевые/прочие
  upstream-ошибки → 502, timeout → 504. Тело ошибки не возвращается Telegram.
- Исходящий `/telegram/send` побайтно сохранён относительно `b1b0e73`.
  `sendMessage` и `getMe` проверены прежними тестами, AI-сервис не затронут.
- Добавлены точные RU-ответы для приветствия, успешной привязки и неверной,
  просроченной или использованной ссылки, с EN-переводами. Известный получатель
  использует свой preferred locale, неизвестный — `TELEGRAM_DEFAULT_LOCALE=ru`.
- Только личный `/start` с положительным целым chat ID и совпадением `from.id`
  может получить ответ. Команды чужого бота, группы, edited updates и обычные
  сообщения игнорируются. Ответы не содержат кодов, имён чужих аккаунтов и ID.

## Дедупликация и задержки

Receipt `telegram_updates.update_id` захватывается для **каждого распознанного
личного `/start`**, включая приветствия и отказ. Receipt и погашение кода находятся
в одной транзакции. Уникальный PK защищает параллельные доставки; блокировка
получателя сериализует создание/ротацию/погашение его кода. Ошибка БД откатывает
receipt и привязку, Laravel возвращает 503 для повторной доставки.
Прежние receipts также продолжают действовать после обновления.

После commit Laravel формирует подтверждение обработки, затем отправляет ответ
бота через termination callback. В PHP-FPM Symfony завершает HTTP-ответ до этого
сетевого запроса. Это устраняет ожидание полного исходящего HTTP-цикла внутри
входящего callback. Повторное выполнение termination callback также защищено.
Фактический web SAPI и задержку после публикации нужно проверить на Jino;
CLI-проверка не определяет возможности web PHP-FPM.

Попытка ответа бота выполняется **не более одного раза** для update. Ошибка,
включая timeout/429/500, не отменяет успешную привязку и не запускает повторное
подтверждение. 403 по-прежнему отключает заблокированный чат. При потере процесса
после commit или неопределённом сетевом результате подтверждение может не дойти:
это ограничение семантики без повторов, а не гарантия доставки ровно один раз.
Статус доступен в приложении, отдельная персональная тестовая отправка сохранена.

## Миграция и диагностика

`2026_10_20_184031_add_chat_hash_to_telegram_connections.php` добавляет nullable
HMAC-индекс чата для определения языка известного получателя без перебора
зашифрованных chat ID. Индекс скрыт из сериализации, ключ — прежний APP_KEY.
Миграция заполняет прежние привязки, не меняя ciphertext, коды, сроки или receipts.
Повторный backfill безопасен; сравнение ciphertext защищает конкурентную перепривязку.

`telegram:check` проверяет оба режима конфигурации без сети/вывода секретов и
возвращает ненулевой код при неполной настройке. `--live` сохраняет одиночный
исходящий `getMe`. Новые env добавлены в оба примера; упаковка релиза требует
новую службу/миграцию и пустой forward secret в шаблоне.

Laravel пишет безопасные стадии received/start/redeemed/rejected/duplicate и
reply sent/failed. Ошибки содержат только канонические error codes. Deno пишет
статус callback и durationMs. Приватное содержимое, коды, chat/update ID,
токены, секреты и полные URL запросов в эти записи не включаются.

Временный `/telegram/diagnostics` и его helper полностью удалены. Даже старый
opt-in флаг не включает маршрут. [Предварительная диагностика](DIAGNOSTICS.md)
завершена: пользователь сообщил production Deno → Laravel health **200 / 1081 мс**,
webhook без секрета **403 / 1072 мс**, неавторизованный diagnostics **401**.
Это не устанавливает первопричину прежнего прямого Telegram → Jino timeout.
