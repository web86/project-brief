# Milestone 4.5.1 — этап предварительной диагностики

Ветка: `codex/milestone-4-5-1-bidirectional-telegram-bridge`.
Основа: Milestone 4.5, `cc5cd445c27759b5aa060fd83ba79dccfcef0b9a`.

По уточнению пользователя сначала подготовлен только временный диагностический
endpoint. Двусторонний callback и новые ответы `/start` будут реализованы после
результатов реального Deno → Laravel запроса. Push, deployment, Release,
регистрация webhook, изменение production secrets и удаление pending updates
не выполнялись.

## Предварительные наблюдения

Без секретов выполнены только локальные проверки с Mac:

| Проба                                           | HTTP | Время   |
| ----------------------------------------------- | ---- | ------- |
| Laravel GET `/api/health`                       | 200  | 950 мс  |
| Laravel POST `/api/telegram/webhook`, JSON `{}` | 403  | 1148 мс |
| Deno POST `/telegram/webhook`, JSON `{}`        | 404  | 646 мс  |
| Deno POST `/telegram/send`, без Bearer          | 401  | 792 мс  |

Эти результаты **не доказывают** доступность Laravel из Deno. Доступа к
production runtime и серверным логам у агента нет. Пользователь организует
нужную проверку через подготовленный endpoint.

Текущий `TelegramController::webhook()` проверяет секрет до привязки и синхронной
отправки подтверждения. Запрос без секрета возвращает 403, не проходя этот путь.
При валидном `/start` исходящий transport может занять до 8 секунд плюс время
PHP/БД; это возможный вклад в задержку, но не доказанная причина сообщённого
Telegram timeout. Неверный/просроченный код и `/start` без кода сейчас игнорируются.
В этом этапе код Laravel не менялся.

## Изменения

- `deployment/telegram-bridge.mjs`: временный `POST /telegram/diagnostics`,
  выключенный по умолчанию. Доступ — только при точном `TELEGRAM_DIAGNOSTICS=1`
  и существующем Bearer `TELEGRAM_BRIDGE_SECRET` длиной от 32 символов.
- Только фиксированные GET health и POST webhook `{}` в Laravel, без секретов.
  Параллельные запросы, отдельный AbortSignal на 8000 мс, без повторов и follow
  redirects. Нельзя передать URL, метод или аргументы из клиентского запроса.
- Результат — HTTP-статус, durationMs и канонический errorCode. Содержимое ответов,
  исключения, заголовки и приватные сведения не возвращаются и не логируются.
  Потоки ответов отменяются без чтения и ожидания зависшего тела.
- Входной JSON ограничен 1024 байтами; непустые опции, query, массивы и невалидный
  JSON отклоняются. При выключении флага — 404 до любых внешних запросов.
- Исходящий `/telegram/send` побайтно сохранён относительно base commit.
  `getMe` и `sendMessage` проверяются существующими тестами.
- `tests/telegram-diagnostics.test.js`: восемь новых тестов для авторизации,
  opt-in, фиксированных адресов, таймаутов, отсутствия утечек, redirect/no-retry,
  зависшего тела ответа и полного отключения.
- В существующую инструкцию Telegram добавлена ссылка на новый этап диагностики.

## Проверки

**15/15 целевых**, **180/180 frontend**, **498/498 Laravel (5054 assertions)**.
Production build и Prettier пройдены. PHP-файлы не менялись; Pint не требовался.
Фактические результаты и локальные пробы: [checks.json](checks.json).

Тесты endpoint выполнялись с Node Fetch mocks, не из опубликованного Deno runtime.
Реальные Deno → Laravel статусы будут известны после ручной проверки пользователя.
Исходящий реальный Telegram запрос, отправка сообщения или изменение webhook
агентом не выполнялись.

## Следующий шаг

Следуйте [DIAGNOSTICS.md](DIAGNOSTICS.md): вручную обновите существующий
Deno-сервис, включите флаг, выполните защищённую проверку с Mac и сразу выключите
флаг. Передайте JSON `checks`, без секретов. При ожидаемых 200/403 можно продолжать
входящий мост; при сетевой ошибке сначала нужен разбор доступности Laravel.
