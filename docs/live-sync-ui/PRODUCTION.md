# Project Brief 0.7.8 — Live Sync и UI: обновление и откат

База: проверенная 0.7.7. Push, merge и production deployment не выполнялись. Эта инструкция предназначена для согласованного обновления после отдельного разрешения.

## Подготовка

Сверьте внешний SHA-256/размер по RELEASE-ARTIFACT.json, CRC и внутренний checksums.txt. Репетируйте на закрытом staging с фактическими PHP 8.4/MariaDB/Jino. Локальные SQLite/PHP 8.5 и headless Chromium не подтверждают production-хостинг или доставку Push провайдером/операционной системой.

Сохраните backup БД, public/private/vendor, deployed `.htaccess`, `.env`, APP_KEY, всего storage/uploads/branding/sessions, scheduler/cron и независимый доступ для отката. Не меняйте Origin/RP ID, MFA, passkeys, sessions, текущие HTTP hardening flags. Не включайте HTTP_BOOTSTRAP_LIMIT_ENABLED до согласованного Jino proxy/NAT/AllowOverride preflight.

## Обновление

1. Остановите записи и scheduler, дождитесь запросов, включите maintenance: `php artisan down` в private app.
2. Замените public/private/vendor комплектом ZIP по DEPLOY-JINO.md. Сохраните `.env`, APP_KEY, весь storage и maintenance marker. Не накладывайте пустой storage пакета на рабочие файлы. Не выполняйте first-install, seed, migrate:fresh, db:wipe, key:generate или security recovery.
3. Выполните в maintenance:

   ```sh
   php artisan migrate --force --no-interaction
   php artisan optimize:clear
   php artisan route:cache
   php artisan config:cache
   php artisan view:cache
   php artisan migrate:status --no-interaction
   php artisan account:security-diagnostics
   ```

4. Новая миграция `2026_10_28_151049_create_project_sync_events_table` создаёт только журнал сигналов UI: bigint cursor, workspace/project, тип сигнала и время; индексы `(workspace_id,id)`, `(project_id,id)`, `created_at`. Текст задач, комментариев, отзывов и приватные заметки в журнал не копируются. Backfill не нужен: обычный bootstrap выдаёт начальный cursor; прежние данные уже загружаются штатными API. Старые миграции, включая `2026_10_26_200540_add_project_trash_lifecycle`, должны быть завершены. Новых зависимостей PHP/Node, Redis, WebSocket, отдельных процессов и cron-задач нет.
5. Прежняя **существующая** hourly-команда `projects:cleanup-files` также удаляет сигналы старше семи дней по индексу времени. Cron не дублировать. Курсор старше шести дней инициирует однократную адресную перезагрузку видимого состояния.
6. Пройдите smoke ниже, после разрешения выполните `php artisan up` и возобновите прежний scheduler. Обновите открытые вкладки обычным способом, дождитесь обновления `/sw.js`. Старый SW сохраняет системные Push, а резервный polling нового приложения не зависит от разрешения Push. Не очищайте пользовательские черновики/сессии/факторы.

## Smoke

- Owner, назначенный developer и клиент: комментарий, новая идея и статус видны без reload; чужие workspace/project и cursor другого пользователя недоступны.
- В отсутствие Push: ни одного дополнительного `/sync` при bootstrap; затем один лёгкий `/sync` через каждые 300 секунд в видимой вкладке. Скрыть/вернуть вкладку, отключить сеть, открыть вторую вкладку того же аккаунта; проверить отсутствие частых повторов и двойных запросов. Ручная проверка сообщений работает независимо от таймера.
- Текст комментария, общей переписки, форма идеи и приватные заметки не теряются при внешнем обновлении. Старый `editVersion` получает 409; пользователь явно подтверждает применение своего черновика к свежей версии. Необязательный параметр сохраняет совместимость со старым frontend; полная защита конфликтов действует в новом bundle.
- Завершить все активные задачи → предложение отзыва; новая/reopened задача → скрытие; повторное завершение → однократное предложение при отсутствии отзыва. Trash исключён, пустой проект не считается завершённым. Уже отправленный отзыв сохраняется, повторная отправка другим клиентом блокируется. Владелец открывает рейтинг/текст/автора/дату, developer/client не могут читать содержимое через admin API.
- Брендинг: длинные RU/EN/TR/ZH названия рядом с логотипом, мобильное меню, обе темы. Сайты `company.com`, `www.company.com`, `https://company.com`, `http://company.com`; опасная схема отклоняется, поле показывает ошибку. Прежние экспорты и настройки флагов сохранены.
- 1440/1280/768/390/360: история читаема без горизонтального scroll; отзыв не перекрывает действия; «Уведомления» имеют только breadcrumbs и стандартный контейнер; немедленное сохранение переключателей не изменено.
- Прежние login/MFA/passkeys, приглашения, trash/restore, JSON/PDF/DOCX и интеграции работают.

## Откат

Остановите записи/scheduler, включите maintenance, верните точный комплект **0.7.7** public/private/vendor. Сохраните `.env`, APP_KEY, весь storage, брендинг, sessions, deployed `.htaccess` и maintenance marker; пересоберите caches старым кодом, пройдите smoke и возобновите HTTP/scheduler.

Журнал `project_sync_events` можно оставить: старый код его игнорирует, пользовательских данных он не меняет. Не выполняйте автоматический `migrate:rollback`: не затрагивайте другие миграции. Удаление только этого вспомогательного журнала допустимо отдельным проверенным шагом после окончательного решения об откате. Отзывы и задачи не удалять; уже сохранённые сайты с `https://` совместимы с 0.7.7.

Обновите вкладки после отката: новый открытый редактор может ещё отправлять необязательный `editVersion`, который старый API не принимает. Ошибка сохранения удерживает черновик; сохраните его перед обновлением вкладки. Старый SW не является cache worker и не кеширует приватные API. Восстановление схемы/данных из backup требуется только при отдельной ошибке обновления, а не для возврата шаблонов UI.
