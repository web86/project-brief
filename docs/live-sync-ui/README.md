# Project Brief 0.7.8 — Live Sync + UI Polish

Ветка `codex/live-sync-ui-polish`, база `codex/milestone-7-7-document-export` / `4de88dfb8cbfddabeadffbcf18a0b8e3e8f5b2cc`. Использованы только собственные синтетические данные. Push, merge и deployment не выполнялись.

## Результат

- Централизованная синхронизация открытого проекта, списка проектов, индикаторов непрочитанного и обоих видов обсуждений. Ручная проверка сообщений имеет отдельный индикатор загрузки.
- Более узкая история в desktop-карточке клиента; на небольших экранах остаётся одна колонка. Длинное название компании переносится рядом с логотипом, без обрезки и горизонтального scroll.
- Сайт компании без протокола сохраняется с `https://`; явный `http://` сохранён. Общий набор примеров проверяет frontend/backend. Опасные схемы и некорректные адреса отклоняются с ошибкой возле поля.
- Страница уведомлений использует стандартный контейнер и breadcrumbs; дополнительное меню удалено. Немедленное сохранение переключателей сохранено.
- Отзыв находится внизу карточки; владелец открывает сохранённые рейтинг, текст, автора и дату. API просмотра проверяет роль владельца и доступ к проекту.
- Предложение отзыва зависит от текущих активных задач: непустой проект, все `done`, trash исключён. Новая или повторно открытая задача прерывает цикл. Повторное завершение разрешает новое однократное предложение, если отзыв ещё не отправлен. Отправленный отзыв сохраняется; повтор другим клиентом блокируется под блокировкой проекта. Прежние исторические отзывы не удаляются.

## Архитектура и нагрузка

`LiveSync` записывает небольшой журнал сигналов после commit: workspace, project, тип, время. Содержимое задач, комментариев и отзывов в журнал не копируется. Порядок ID сериализован блокировкой workspace, поэтому более поздний commit не может перескочить ранее незавершённое событие. Очистка за семь дней включена в существующую hourly-команду `projects:cleanup-files`; новых cron, процессов, Redis и WebSocket нет.

Начальный зашифрованный курсор приходит с обычным `/admin/me` либо client project bootstrap. Дополнительного стартового запроса нет. Один координатор приложения проверяет `/sync` через **300 секунд**, приостанавливает таймер скрытой вкладки, не запускает параллельные проверки и выдерживает тот же интервал после ошибки. Возврат вкладки вызывает проверку только по истечении интервала. На страницах аккаунта без загруженного workspace контекста синхронизация не запускает дополнительные bootstrap-запросы.

BroadcastChannel передаёт курсор и сигналы между вкладками одной личности/workspace; Web Locks предотвращает одновременный опрос. localStorage хранит только время проверки и receipt последнего Push, без данных API. Service Worker сохраняет прежнее системное уведомление и отправляет открытым окнам сигнал. Повтор одного Push объединяется; дополнительный toast не создаётся. Push не обязателен для polling.

Обычная проверка выполняет **один индексированный запрос журнала**, ограниченный 101 строкой, с проверкой видимости проекта через correlated EXISTS. Нет обхода всех проектов и нет запросов на каждый результат. В измеренной авторизованной HTTP-проверке всего 9 SQL-запросов с учётом сессии, middleware и прав. Переполнение окна или устаревший курсор возвращает reset. Тяжёлые данные перечитываются только при изменении и только для видимого контекста; список проектов сохраняет штатную пагинацию и фильтры.

За 15 виртуальных минут с реальными HTTP-запросами: **22 → 25 запросов**, **7922 → 8894 байта** декодированных ответов. Разница — ровно **3 `/sync`, 972 байта**. Исходные 15 `/security/status` и 7 `/security/passkey/confirm/options` относятся к существующему security step-up и не менялись. Измерение не включает HTTP/TLS-заголовки. Это локальная проверка, не замер нагрузки Jino.

## Черновики и конфликты

Обновление не заменяет локальные формы, тексты комментариев и developer drafts. Запросы обновления объединяются; старый ответ не перезаписывает собственную более новую запись. Для редактируемых полей сервер возвращает HMAC `editVersion`; устаревшее сохранение получает 409. Пользователь явно применяет свой черновик к новой версии. Версия клиента не включает закрытые оценки, цены и заметки. Удалённая извне задача остаётся только как локальный черновик с предупреждением, затем удаляется из локального состояния после выхода/отмены.

Необязательный токен сохраняет совместимость со старым frontend. Защита конфликтов действует для новых редакторов; уже существующие API-клиенты без токена сохраняют прежнее поведение. При откате необходимо обновить открытые вкладки, предварительно сохранив черновики.
