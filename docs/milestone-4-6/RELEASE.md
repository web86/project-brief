# Project Brief 0.4.6 — централизованные уведомления и UX

Полный production ZIP для обновления с 0.4.5.1. Готовые Vue assets, Laravel,
production vendor и все миграции включены; серверные Composer/Node не нужны.

**До загрузки прочитайте PRODUCTION.md.** Сохраните БД, `.env`, прежний APP_KEY,
всё storage/uploads, сессии и секреты каналов. Загружайте только:

```text
private/project-brief-app/ → ~/project-brief-app/
public/                   → ~/domains/brief.web86.site/
```

На действующем приложении включите maintenance, замените код/vendor/assets,
сохранив `.env` и непустой storage. Затем:

```sh
cd ~/project-brief-app
php artisan config:clear
php artisan migrate --force
php artisan optimize
php artisan up
```

При ошибке не выполняйте `up`. Нельзя создавать новый APP_KEY, выполнять
fresh/wipe/seed или очищать историю доставок. Новая миграция:
`2026_10_20_201536_centralize_notification_preferences.php`.
Новых env нет; Deno, настоящий webhook и его очередь **не меняются**.
Файл `deployment/telegram-bridge.mjs` в ZIP сохранён без изменений для справки.

В «Мои настройки → Уведомления» каждый User управляет своими каналами для всех
проектов и workspace. Новый Email требует одноразового подтверждения по почте.
Старые разные адреса сохранены и показаны для осознанного выбора единого адреса.
Подписки Push и привязки Telegram сохраняются.

Проектный экран содержит события и адресатов. Прежняя матрица действует до
подтверждения перехода; новая модель использует личные каналы получателей.
Переход может разрешить канал, ранее выключенный только в проекте, если получатель
разрешил его у себя. Личные запреты принудительно не включаются. Доступ адресатов
проверяется при сохранении и непосредственно перед доставкой.

Включены шесть UX-исправлений: лишняя подпись над H1 удалена; стрелка карточки
остаётся только у клиента; счётчик расположен рядом с разделом; на странице
разработчика убраны выбор раздела/стрелки сортировки; «В работе» имеет стабильные
точки с reduced-motion, «Согласовано» зелёное; клиентские обсуждения, уведомления
и экспорт получили общую горизонтальную навигацию и возврат к идеям.

Регрессия Laravel/frontend, браузерная матрица, build, Pint и Prettier входят
в проверку исходников. Сборщик отдельно проверяет production vendor, отсутствие
секретов, целостность ZIP/SHA-256 и работу упакованного приложения на временной БД,
включая миграции, личные настройки и подтверждение адреса. Итоговые метрики —
в сопровождающем build-report.json рядом с ZIP.

Реальная доставка после обновления проверяется оператором по PRODUCTION.md:
отдельной среды нет, этот порядок согласован пользователем. Агент не выполнял
push, deployment, изменение webhook или публикацию GitHub Release.
