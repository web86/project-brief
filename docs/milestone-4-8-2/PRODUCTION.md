# Milestone 4.8.2 — production patch

Применять только поверх **Milestone 4.8.1, commit `edc141d`** (полный релиз 4.8 `6ab3389` + patch 4.8.1). Этот patch не заменяет предыдущие обновления.

Состав: `private/project-brief-app/app/Services/AccountProfile.php`, изменившиеся frontend assets и `public/index.html`. В ответ профиля добавлен непрозрачный `notificationPreferenceId`, стабильный при смене Email и общий для аккаунта во всех workspace. Внутренний ID пользователя по-прежнему не возвращается. Он нужен исключительно для локального предпочтения закрытия баннера. API сохранения, права, сессии и бизнес-логика не изменены.

Vendor, `.env`, storage, пользовательские файлы и БД не включены. Новых зависимостей и миграций нет. Сохраните существующий APP_KEY: он участвует в вычислении непрозрачного идентификатора. Ротация APP_KEY также сбросит привязку закрытия баннера.

## Установка

1. Проверьте, что установлен 4.8.1. Сверьте SHA-256 заменяемых файлов с `BASE-CHECKSUMS.txt`; он описывает установленный релиз 4.8 + patch 4.8.1. Если контрольные суммы отличаются, сначала выясните причину и сопоставьте локальные изменения. Проверьте SHA-256 самого ZIP по соседнему `.sha256` и файлы распакованного patch по `checksums.txt`.
2. Сохраните текущий `~/project-brief-app/app/Services/AccountProfile.php`, публичный `index.html` и текущие assets. В Laravel-каталоге `~/project-brief-app` выполните `php artisan down`.
3. Наложите `private/project-brief-app/` на существующий `~/project-brief-app/`, а `public/` на `~/domains/brief.web86.site/`. Сначала загрузите новые assets и PHP-файл, затем замените `index.html`. Старые hashed assets **оставьте** для открытых страниц и отката. Это добавление/замена файлов, без удаления содержимого каталогов.
4. В каталоге Laravel выполните:

```sh
php artisan optimize:clear
php artisan optimize
php artisan up
```

Если OPcache не проверяет timestamps, сбросьте его через панель хостинга или перезапуск PHP. Composer/npm, миграции, переустановка и смена APP_KEY не требуются. ZIP, manifest и инструкции не размещайте в document root.

5. Обновите страницу браузера, чтобы загрузить новый `index.html`. Проверьте клиентский проект и личные уведомления, администраторские уведомления, sidebar при ширине >960px, Drawer на мобильном и отсутствие sidebar на страницах отдельной задачи. Проверьте обе темы и RU/EN. Убедитесь, что закрытый баннер не возвращается после reload и закрытие не переносится на другой аккаунт. При заблокированном браузером localStorage закрытие действует до завершения текущего сеанса страницы.
6. Сохранение персональных разрешений клиента требует кнопки «Сохранить уведомления»; администраторские разрешения применяются только после ответа API. Telegram-подключение и персональное разрешение — отдельные настройки. Подтверждение Email и Push-разрешения браузера работают прежним способом.

## Откат

`php artisan down` → восстановить сохранённый `AccountProfile.php` и предыдущий `index.html` → `php artisan optimize:clear` → `php artisan optimize` → при необходимости сбросить OPcache → `php artisan up`. Старые assets оставлены, поэтому старый index.html продолжит работать. Новые hashed assets можно удалить позже после проверки, что они больше не нужны.

Patch не меняет схему БД. Пользовательские изменения настроек, выполненные во время эксплуатации, сохраняются. Ключи закрытия баннера в localStorage безвредны для старого интерфейса, удалять их для отката не требуется.

## Воспроизводимая сборка

После коммита и проверок:

```sh
node deployment/build-notifications-ui-patch.mjs
```

Сборщик проверяет чистый Git checkout, базовые commits/версии и контрольные суммы предыдущего patch. По умолчанию нужны:

- `release/project-brief-20261025-133055-6ab3389.zip`;
- `release/project-brief-0.4.8.1-patch-edc141d.zip`.

Другие пути задаются через `M482_BASE_ZIP` и `M482_BASE_PATCH`. Допустимое backend-изменение — только `AccountProfile.php`. Сборщик собирает frontend в API-режиме, сравнивает файлы с базой, накладывает оба patch на полный релиз в изолированном каталоге, проверяет runtime и отсутствие секретов, выпускает ZIP, SHA-256, `PATCH.json`, `BASE-CHECKSUMS.txt` и `checksums.txt`. ZIP не содержит test fixtures, скриншоты и исходники frontend.

Deployment и push этим workflow не выполняются.
