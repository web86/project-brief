# Agent security model

Service identity is an external_agents record within a workspace, never a fake human user or platform/superadministrator. kind is a display/connection label and never grants permissions. Project membership extends project_members; explicit owner grants bound the project choices available to project superadministrators. TaskAgentAssignment is a generation-bound work assignment, not a duplicate project participant model.

Authorization intersects credential scopes, token validity, active registration, workspace, owner project grant, existing project membership, live active project/task and current assignment generation. Foreign/unassigned UUIDs return 404. Generic integration APIs reject agent credentials before dispatch. Agents cannot edit tasks, approve client work, change task statuses, remove files, invite users, manage team/project settings, integration secrets or their own permissions. Human session routes retain MFA, fresh confirmation and tenancy checks. Deactivation revokes credentials even when later reactivated.

Writes use strict field allowlists and existing validation, hashed idempotency records, replay authorization and generation checks. A workspace row lock serializes agent requests/control mutations, with nested transaction rollback and filesystem cleanup. Duplicate files/comments/reports under a key are not recreated. Task trash also takes that workspace lock. Tokens never appear in URL, logs, errors, notification content or stored plaintext. Credential UUIDs identify the actor in audit. Only one-time issue responses contain raw secrets and use no-store. Keep credentials outside screenshots and source control; issue minimal scopes, explicit project grants and expiry.

All report text/URLs/files are untrusted input. Vue renders text as escaped strings; no shell, PHP, Node, Python, prompt or tool execution occurs on the application server. HTTPS result URLs reject credentials/control characters, are never fetched server-side and open with noopener/noreferrer. Existing SafeAttachment rules enforce type/MIME and image/archive checks; private files remain outside document root and use existing authorized download routes. There is no antivirus or E2EE claim. Agents cannot read task attachments, comments or private chat through Agent API in this milestone.

Webhook recipients have independent encrypted signing secrets. Existing SSRF defenses, public DNS checks and cURL pinning, bounded response/time/retry, signatures and journals are preserved. Delivery rechecks the assignment; events pending before revocation cannot disclose data afterward. Only IDs and execution state enter agent webhook payloads. Existing general webhook recipients keep their separately owner-authorized project subscriptions.

agent_operations records agent/workspace, credential ID, normalized route/method, HTTP status/time and project/task/assignment UUID when the task was resolved. Failed object probes omit inaccessible IDs. Agent cards show successful/failed authenticated request counters and last successful activity. Invalid unrecognized/revoked bearer requests receive 401 before reaching agent business operations; existing hourly global API metrics cover response status. No request body, query string, auth header, task text or token secret is copied into diagnostics. Audit identities/results survive soft deletion. Existing task history carries explicit agent actor and linked assignment/credential UUID. No production credentials are transferred by the integration itself.

Plan limits, billing, token cost accounting and MCP are intentionally absent. Registration, project grants, credentials and operation counts are separate and can support future entitlements without changing authorization scopes.

Before production enablement review external-provider retention/data handling, narrowly select projects and task descriptions, verify local/staging tests, HTTPS and private storage, back up DB/storage/APP_KEY and validate revocation. Local PHP/MariaDB/browser evidence does not prove Jino/FPM, external provider or physical device behavior.
