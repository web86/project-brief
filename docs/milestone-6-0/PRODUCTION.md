# Project Brief 0.6.0 — установка и проверка

Production deployment автоматически не выполняется. ZIP содержит согласованные `public/` и `private/project-brief-app/`, production vendor, checksums и документацию.

Перед ручным обновлением проверить SHA-256 архива и source commit в `release.json`. Сохранить резервную копию БД, приватных файлов, текущих public/private, `.env`, APP_KEY и всех действующих секретов. Использовать существующую раздельную структуру из DEPLOY-JINO.md.

На время ручного обновления приостановить cron, дать текущим попыткам завершиться, включить maintenance и установить обе части одного архива. Новых миграций, env-переменных, каналов и сервисов в 6.0 нет. Затем из приватного приложения:

```sh
php artisan down
php artisan migrate --force --no-interaction
php artisan optimize:clear
php artisan up
```

Возобновить прежние cron/queue. Настройки каналов и error-only logging сохраняются; подробности предыдущего этапа находятся в `GUIDES/milestone-5-0-3/PRODUCTION.md`.

Проверить RU/EN/TR в администраторе и клиентском доступе, выбор и сохранение языка, повторный вход с другого браузера, `/app`, новую вкладку после обновления и существующий service worker. Проверить тестовые уведомления только на собственных тестовых каналах и по одному реальному событию для согласованных тестовых получателей. Проверить независимый язык PDF/DOCX, символы `ç ğ ı İ ö ş ü`, USD/RUB/EUR/TRY исходного проекта. Пользовательский текст не должен переводиться.

При откате вернуть согласованный предыдущий комплект public/private и очистить кеш приложения. Существующее `preferred_locale` может содержать `tr`; предыдущая версия его не поддерживает. Не изменять эти предпочтения массово: согласовать поведение fallback либо оставить текущую версию до исправления. Новых таблиц и полей для удаления нет.

Локальные SQLite/Chromium и изолированные транспорты не подменяют приёмочную проверку реального хостинга, SMTP, Telegram и Web Push.
