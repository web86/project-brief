# Milestone 4.3 — визуальная приёмка

Выполнен первый этап из задания: локальный визуальный прототип публичной главной и сценария демо. Продакшен-маршруты, Laravel, авторизация, клиентские ссылки и PWA не изменены. Push, release и deployment не выполнялись.

## Запуск

Из корня репозитория:

```sh
npm run preview:public
```

Открыть <http://127.0.0.1:5183/> или <http://127.0.0.1:5183/demo>. Это отдельный Vite entry, включая прямой вход и перезагрузку `/demo`. Рабочее приложение по-прежнему запускается через `npm run dev` на порту 5173; кнопки «Войти» и «Открыть приложение» ведут к нему на `/app`. Для визуального прототипа запуск API не нужен.

```sh
npm run build:public-preview
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs npm run test:public-preview
```

Сборка прототипа находится в `artifacts/milestone-4-3-preview/` и исключена из Git. Обычная production-сборка по-прежнему использует существующий `index.html` и `src/main.js`; прототип в неё не включён. Новых зависимостей нет.

## Экраны и навигация

1. **Hero.** Существующий знак ProjectBrief, крупное позиционирование, две кнопки и переключатель ролей. Одна и та же задача «Обновить первый экран» показана как пожелание клиента или как рабочая карточка с оценкой, согласованием и обсуждением. На телефоне показана карточка задачи без уменьшенного desktop-sidebar.
2. **Как работает.** Три последовательных шага: описать идею → обсудить и согласовать → следить за выполнением.
3. **Для клиентов.** Простой язык, помощь в формулировке и прозрачность. Тёплая иллюстрация связывает исходную мысль с подготовленным примером задачи.
4. **Для разработчиков.** Контекст проекта, оценки и история. Иллюстрация показывает жизненный цикл той же задачи.
5. **Один проект — две стороны.** Две карточки рядом на desktop и последовательно на телефоне: пожелание и прогресс / структура и рабочие детали.
6. **Приглашение в демо и footer.** Повторная кнопка `/demo` и компактное завершение страницы.
7. **Демо.** Один проект с девятью задачами на основе `createDemoData()`. Переключение ролей сохраняет выбранную задачу. Можно фильтровать, читать обсуждения, раскрывать заранее подготовленный пример AI, добавлять идею в native dialog и начинать заново.

«Возможности» и «Как работает» ведут к секциям главной; «Демо» и обе основные CTA — на `/demo`. Логотип и «На главную» возвращают к `/`. RU/EN и светлая/тёмная/системная темы переключаются без перезагрузки.

## Границы демо и проверки

- Отдельный entry не импортирует проектные Pinia stores, API client, session service или service worker. Сборка явно использует `VITE_DATA_SOURCE=api`: изоляция не зависит от глобального demo mode.
- Данные создаются из безопасной фабрики `src/data/demo.js`, затем локализуются для примера. Дополнительное обсуждение первой задачи — синтетический сценарий, не пользовательская переписка.
- Состояние задач и языка живёт в Vue refs. Существующий theme resolver используется с окружением без доступа к localStorage. Реальные настройки приложения не читаются и не изменяются.
- AI обозначен как заранее подготовленный пример. Для введённой пользователем идеи ответ AI не выдумывается. Сохранение на сервере, экспорт, изменение статуса и отправка комментариев не имитируются.
- Browser-проверка прошла: RU/EN без непереведённого русского текста в EN, обе роли, три режима темы, отсутствие переполнения, выбор задач, фильтры, пример AI, добавление идеи и её исчезновение после reload, прямой `/demo`, focus в dialog и возврат после Escape.
- За весь сценарий: **0 API-запросов, 0 внешних запросов, 0 browser errors**. Содержимое localStorage до и после сценария совпало. Результат: [results.json](results.json).
- Поддерживается reduced motion, в том числе при переходе к якорям. Используются native buttons/select/dialog, видимый focus и skip link. Это не полный аудит доступности: он входит в интеграционный этап.

## После визуальной приёмки

Только после приёмки переносить утверждённую компоновку в production entry и завершать интеграционные проверки:

1. **Router / App.** `/` и `/demo` получают публичный layout без sidebar, push-контролов и toast-уведомлений рабочего проекта. Убрать только перенаправление `/` в `/app`; сохранить переход по сессии в `/app`, admin/client guards, magic links и проверку несохранённых developer drafts. Публичные маршруты не должны запускать bootstrap проекта или загрузку данных. При этом переход из рабочего редактора на публичную страницу обязан проверять несохранённый черновик.
2. **Изоляция в общей SPA.** Сохранить отдельный in-memory state демо и не подключать к нему существующий глобальный demo mode, API либо клиентский language switcher с PATCH-запросом. Публичная компоновка не должна реагировать на оставшиеся в рабочем store ошибки или потерю сессии. Проверить вход в `/demo` из активной admin/client session и возврат в приложение.
3. **Laravel SpaController.** Сейчас возвращает общий SPA HTML для разрешённых GET/HEAD, исключая API/access/sanctum. При интеграции сохранить эти ограничения и существующие backend magic-link routes.
4. **SEO.** Для небольшой публичной страницы предпочтителен build-time prerender двух языковых вариантов: основной маркетинговый текст присутствует в HTML без выполнения JS, затем Vue гидратирует переключатели. Тяжёлая request-time SSR-архитектура этому сценарию не требуется. Проверить гидратацию, не допустить попадания сессии или задач в HTML и согласовать стабильные URL языковых версий. Title/description, `lang`, canonical, `hreflang`, OG/Twitter и social preview формировать для каждого языка из единого контента и настроенного публичного origin. Демо — `noindex`; приватные SPA-маршруты — `X-Robots-Tag: noindex, nofollow` без приватных данных в метаданных. Ограничения robots не заменяют авторизацию.
5. **Проверки перед завершением.** Production build с `VITE_DATA_SOURCE=api`, существующие frontend/backend regression tests, активные admin/client sessions, magic links, draft leave guard, PWA и service-worker navigation fallback, отсутствие API/Groq-запросов в демо и адаптивность публичных страниц.

Текущий прототип намеренно помечен `noindex, nofollow`. Production canonical/OG, prerender и изменение индексации не включены в первый этап; они требуют интеграции после визуальной приёмки по заданию.
