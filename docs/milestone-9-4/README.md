# Project Brief v0.9.4

Milestone 9.4 продолжает v0.9.3: исправлены персональные страницы с брендом текущего workspace, добавлены мобильные жесты существующих drawer и клиентские действия со статусом review. Новых зависимостей, workflow, таблиц или миграций нет. Функции администраторов, SSO, Passkey и соглашений v0.9.3 сохраняются.

## Брендирование

Первопричины: `activeWorkspaceBrand` намеренно исключал `personalSettings`, а персональный bootstrap `/api/admin/notifications` не возвращал workspace branding. После F5 магазин не имел источника оформления. Общий механизм теперь использует безопасную проекцию `CurrentWorkspace::state`, один navigation store и существующие CSS tokens. Персональные предпочтения остаются глобальными. Отдельно на четырёх PHP workers воспроизведена гонка: старый фоновый HTTP-запрос записывал прежнюю сессию поверх нового workspace_id. Включена штатная блокировка stateful requests Laravel с существующим file cache lock store: запросы одной сессии выполняются последовательно; разные сессии остаются независимыми. Без сериализации только write endpoint не защищён от конкурирующих read endpoints, которые тоже сохраняют сессию. Нового session handler нет.

Выбранный workspace проверяется по активному membership. Если выбора нет, бренд допустим только при одном активном workspace; неоднозначный, устаревший или чужой выбор даёт Project Brief. `/platform` сохраняет собственное оформление. При переключении revision guard игнорирует устаревший ответ, очищает project state; логотип и футер временно скрывают чужой бренд без скачка layout. Настройки банковских реквизитов и приватные контакты не публикуются. Телепортированный клиентский drawer получает те же CSS tokens без дополнительного API.

## Редактор соглашений

На /admin/settings/agreement удалён дублирующий preview. Компактная icon toolbar использует AppIcon, локализованные title/aria-label и active states; на мобильном прокручивается сама панель. Нативный contenteditable и execCommand сохраняют Undo/Redo; ссылки вставляются/редактируются через BaseDialog с сохранённым Range, удаляются отдельной кнопкой. Для редактора доступны H1/H2; публичный документ сохраняет вложенную семантику под заголовком страницы. Смежные элементы списков отображаются одним списком, включая последовательную нумерацию после reload.

Документ по-прежнему хранится структурированными блоками. К span добавлено только необязательное href. Клиент и Laravel разрешают http/https без credentials и mailto с email без параметров; активные схемы и произвольные атрибуты запрещены. Общий renderer экранирует текст и создаёт только фиксированные теги/атрибуты, ссылки имеют target=_blank и rel=noopener noreferrer. Черновик, опубликованная версия и acceptance page используют тот же источник. Новых таблиц, зависимостей и изменений gate нет.

## Мобильные жесты

Общий небольшой matcher подключён к существующим admin/client/task drawers. Открытие начинается в полосе 0–28 px, требует минимум 56 px вправо, горизонтального преобладания 1.8, не более 40 px вертикального смещения и 800 ms. Закрытие — влево внутри текущего drawer. Desktop, mouse, формы, ссылки/кнопки, текстовое выделение, вкладки и горизонтальная прокрутка исключены. Модальное окно предотвращает открытие второго drawer. Vertical intent, отмена touch, blur, pagehide и browser navigation сбрасывают попытку; listeners снимаются при unmount.

Pointer Events и пассивный Touch Events fallback учитывают отмену pointer-потока при нативном panning. Нет preventDefault, pointer capture, touch-action override или перехвата системного Back. На iOS/Android браузер может забрать зарезервированный edge-жест; в этом случае остаётся гамбургер. Меню открывается после распознанного завершения; существующая анимация, backdrop, focus и scroll lock сохранены. Перетаскивание меню вслед за пальцем не добавлено.

## Статусы клиента

Согласованный переход возврата — `review → approved` («Согласовано»), кнопка «Вернуть в согласованные». `clientApproved` и прежнее согласование требований остаются отдельным существующим признаком.

| Исходный статус | Допустимая смена статуса клиентом                    |
| --------------- | ---------------------------------------------------- |
| new             | Нет; прежние редактирование и согласование сохранены |
| clarification   | Нет; прежняя логика сохранена                        |
| approved        | Нет; прежняя логика сохранена                        |
| in_progress     | Нет                                                  |
| review          | approved; done после UI-подтверждения                |
| done            | Нет                                                  |

Laravel сам проверяет клиентскую сессию, проект, задачу, текущий статус и editVersion под прежними project/task locks. Клиентский status PATCH не может содержать другие изменения. При устаревшей версии — 409; Vue загружает актуальную задачу и не повторяет запись. Отмена не отправляет PATCH, ошибки не меняют статус оптимистично, повторный клик блокируется. Владелец и назначенный разработчик сохраняют все прежние переходы. История, live sync, webhook и progress используют штатный путь; событие `client.task_status_changed` добавлено в существующие каналы и настройки уведомлений с локализацией.
