# Рабочее место разработчика

Проверено 5 октября 2026 года. Изменения продолжают текущий MVP:
ProjectView, TaskFormView и сетка карточек не менялись; новых зависимостей нет.

## Layout и компоненты

- DeveloperPanel заменён на DeveloperTaskPanel: status select, контекстные
  действия, компактные часы и стоимость, состояние согласования.
- DeveloperNotes — отдельный широкий блок с локальным черновиком и явным сохранением (Milestone 1, 8 октября 2026).
- QuickStatusActions — контекстные кнопки, общий helper `taskWorkflow.js`
  вызывает только существующий `changeStatus()`. События истории не дублируются.
- TaskView объединяет клиентское ТЗ, панель, комментарии, заметки и свёрнутую историю.
- CommentForm предоставляет метод фокусировки через ref; CommentList имеет короткий empty state.
- Currency helper отображает RUB/₽, USD/$, EUR/€, TRY/₺. Новые демо-проекты
  используют `currency: 'RUB'`; старые снимки без поля продолжают работать с ₽.

На desktop 1440×900 ширина колонок — 786 и 476 px (примерно 62%/38%).
ТЗ и панель начинаются на y=259, комментарии — y=621, заметки — y=500
для короткого ТЗ и y=661 для прежней задачи с двумя файлами.
Все эти блоки видны хотя бы частично на первом экране. История находится
под обеими колонками и занимает всю ширину.

На mobile 390×844 порядок: ТЗ → управление → комментарии → заметки → история.
Комментарии идут сразу за управлением, чтобы вопрос после «Нужно уточнить»
оставался рядом с действием. Порядок DOM и фокуса совпадает с визуальным порядком.
Все блоки шириной 354 px, кнопки не ниже 44 px. Горизонтальной прокрутки нет,
включая location с URL длиной 419 символов.

## Workflow и согласование

| Статус         | Быстрые действия                   |
| -------------- | ---------------------------------- |
| Новая идея     | Всё понятно; Нужно уточнить        |
| Нужно уточнить | Всё понятно; Взять в работу        |
| Согласовано    | Взять в работу                     |
| В работе       | Отправить на проверку; Завершить   |
| На проверке    | Завершить; Вернуть в работу        |
| Готово         | Задача завершена; Вернуть в работу |

«Всё понятно»: с согласованием клиента переводит в `approved`, без него
оставляет/возвращает `new` и сообщает об ожидании согласования. Отдельное
состояние developerReviewed не добавлено. `clientApproved` меняет только
клиент через прежнюю кнопку. Завершение и возврат в работу не меняют этот флаг;
он отражает согласованный объём ТЗ, а не приёмку выполненной работы.

«Нужно уточнить»: status становится `clarification`, затем CommentForm после
`nextTick()` фокусирует textarea и при необходимости прокручивает её в видимую область.
Placeholder — «Что нужно уточнить у клиента?». Сообщение отправляется только кнопкой.
Для reduced motion прокрутка выполняется без анимации.

## Проверка в браузере

- Новая тестовая идея без client approval: «Всё понятно» не меняет статус/согласование.
- Уточнение меняет badge/select, фокусирует поле и не добавляет комментарий.
  На mobile поле после прокрутки находится между y=387 и y=457 при высоте 844 px.
- Проверены все быстрые переходы из `approved`, `clarification`, `in_progress`,
  `review`, `done`; каждое изменение статуса добавляет ровно одно событие.
- Status select работает, завершённая задача допускает комментарии и возврат в работу.
- При нажатии Enter на быстрой кнопке фокус сохраняется в workflow:
  после отправки на проверку — «Завершить», после завершения — «Вернуть в работу».
- Согласование в client mode работает. Developer-only поля и кнопки отсутствуют.
- На тестовой идее введены 5,5 часа, 13750 ₽, многострочная заметка и сообщения
  обоих участников. После перезагрузки все данные восстановились.
- Прежняя задача с галереей сохранила 3,5 часа, 15000 ₽, заметку, два вложения,
  два комментария и согласование. Старый проект без currency показывает ₽.
- История по умолчанию закрыта, Enter раскрывает/сворачивает timeline на mobile.
- Консоль: ошибок и предупреждений нет.

Сценарии изменения статусов проверялись на прежней тестовой идее
«Проверка UX: мобильное меню»; рабочие демо-задачи не изменялись.

## Milestone 1 — явное сохранение, 8 октября 2026

Оценка, стоимость и технические заметки больше не отправляются по таймеру,
blur/change, при смене маршрута, выходе или загрузке/перемещении проекта.
Изменения остаются в памяти отдельно от серверного состояния. Под заметками
показываются «Есть несохранённые изменения» и «Сохранить изменения».
Одна кнопка сохраняет все изменённые поля задачи одним PATCH; Cmd+S / Ctrl+S
работает только в открытом редакторе задачи с несохранёнными изменениями.

Успех обновляет серверное состояние и показывает глобальный toast. Ошибка
сохраняет черновик для повторной попытки. Ввод во время запроса остаётся
черновиком для следующего сохранения. Навигация и выход требуют подтверждения
отмены черновика; beforeunload подключён только пока есть несохранённые изменения.
Сохранения без изменений не отправляются. Локальное восстановление после reload
не добавлено: если подтвердить закрытие/перезагрузку, черновик будет потерян.

История оценки/стоимости сохраняет old/new, заметки — только факт изменения.
Статусы, согласование и комментарии по-прежнему выполняются сразу.
Подробности уведомлений и проверок: [Milestone 1](milestone-1.md).
