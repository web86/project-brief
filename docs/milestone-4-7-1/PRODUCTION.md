# Project Brief 0.4.7.1 — обновление

Исходная база — Milestone 4.6.1, commit `3023f57`. Отдельной ветки Milestone 4.7
в доступном репозитории нет. Готовый ZIP содержит приложение, production vendor,
готовые frontend assets и все прежние миграции. Целевой PHP — 8.4.

В начале задания пользователь разрешил отправить текущее состояние в main:
на GitHub `web86/projects-manager/main` обновлён до `3023f57`. Изменения 4.7.1
подготовлены в локальной ветке `codex/milestone-4-7-1-navigation-layout`.
Deployment и GitHub Release не выполнялись.

## Что меняется

На страницах проекта левый сайдбар содержит проектную навигацию. Вверху —
«Все проекты», ниже — существующие разделы; последней стоит «Корзина» с
разделителем. Корзина открывает прежний диалог и сохраняет восстановление идей.
На детальной странице идеи остаётся навигатор задач, проектное меню доступно
через существующую правую панель. Личные уведомления и выход доступны из меню.

На главной проекта H1 и прогресс с добавлением идеи образуют две равные колонки
на desktop и tablet. На mobile заголовок находится сверху. Мобильный фильтр
статусов — native select со счётчиками. При переходе на ширину 640 px и меньше
фильтр разделов сбрасывается на все разделы и скрывается. Выбор статуса остаётся
общим с desktop-кнопками. Клиентский интерфейс сохранён.

В текущей базе существуют личные уведомления, но нет отдельных маршрутов
личного профиля, безопасности и команды проекта. Неработающие пункты для них
не добавлены. Новых backend routes, зависимостей или env-переменных нет.

## Резервная копия и загрузка

Сохраните БД, действующую `.env`, APP_KEY, всё `storage/`, uploads, сессии,
текущий код/vendor и public assets. Сохраните SMTP, VAPID и Telegram secrets.

В действующем `~/project-brief-app`:

```sh
php artisan down
```

Загрузите содержимое архива по прежней схеме Jino:

```text
private/project-brief-app/ → ~/project-brief-app/
public/                   → ~/domains/brief.web86.site/
```

Замените vendor целиком. Не перезаписывайте рабочую `.env`, APP_KEY и содержимое
storage пустыми каталогами архива. Сохраните maintenance marker, права каталогов
и скрытые public files. Удалите старые скомпилированные файлы bootstrap/cache,
сохранив каталог. ZIP, private, мост и инструкции не размещайте в document root.
Подробная схема — DEPLOY-JINO.md.

```sh
php artisan config:clear
php artisan migrate --force
php artisan optimize
php artisan up
```

В 4.7.1 новых миграций нет. Если production ещё на 4.6, будет выполнена прежняя
безопасная миграция 4.6.1 `2026_10_25_074255_add_deleted_at_to_tasks_table.php`:
nullable deleted_at и индекс, без переписывания существующих данных.
Не выполняйте key:generate, first-install, migrate:fresh, db:wipe или seed.
При ошибке migration/optimize оставьте maintenance до устранения причины.
Node/npm/Composer на сервере не нужны — assets и production vendor включены.

Deno-мост, Telegram webhook и система отправки уведомлений не изменены.
Повторный deployment моста, setWebhook, deleteWebhook и сброс pending updates
для этого обновления не требуются.

## Проверка после обновления

1. Обновите вкладки. Проверьте `/api/health`, вход и рабочую клиентскую ссылку.
2. На `/admin` и личных уведомлениях должен остаться глобальный сайдбар.
3. Откройте идеи, обсуждения, клиентов, структуру, уведомления проекта,
   настройки и экспорт. Должны работать активная ссылка и счётчик обсуждений,
   без горизонтального дубля. «Все проекты» возвращает на `/admin`.
4. На телефоне откройте меню: оно должно содержать текущий проект и закрываться
   после перехода. Проверьте Escape/Tab и доступ к личным уведомлениям/выходу.
5. Откройте идею: навигатор задач, панели и редактор сохраняются. Попробуйте
   выйти с несохранёнными изменениями и отменить выход — черновик должен остаться.
6. Проверьте шапку на 1440/1280/768/390/320 и длинном названии. H1 один.
   На остальных страницах прогресс с кнопкой не отображается.
7. На desktop выберите раздел и статус; уменьшите окно до mobile. Скрытый
   фильтр разделов не должен ограничивать список. Верните desktop и проверьте
   общий статус. При частичной фильтрации перенос идей отключён.
8. Проверьте mouse/touch перенос, сохранение/reload, ошибку API и откат,
   корзину из настроек и страницы идеи, восстановление и сохранность вложения.
9. Переключите workspace через «Все проекты». Старое проектное меню должно
   исчезнуть. Проверьте владельца и приглашённого разработчика; при отказе
   доступа старые пункты и загруженные задачи должны очищаться.
10. Проверьте RU/EN, light/dark/system и неизменённый клиентский интерфейс.

Локальные браузерные тесты используют API fixtures; HTTP-тесты production-пакета
запускают настоящее приложение на временной БД. Реальные Email/Push/Telegram
сообщения пользователям не отправлялись.

## Откат

В maintenance восстановите предыдущий код/assets и при необходимости согласованную
резервную копию БД. Откат к 4.6.1 не требует отката схемы: новых миграций нет.
Не удаляйте deleted_at и не откатывайте только код к 4.6 после использования
корзины — старая версия покажет скрытые идеи. APP_KEY и storage сохраняйте.
