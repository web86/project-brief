# Milestone 4.7.1 — отчёт

Исходная база — готовый Milestone 4.6.1, `3023f57`. Ветка реализации:
`codex/milestone-4-7-1-navigation-layout`.

В начале задания прямо разрешён push текущего состояния в main. Выполнен
обычный fast-forward push `3023f57` в `web86/projects-manager/main`; результат
проверен через GitHub API. Изменения 4.7.1 остаются локальными. Deployment
и GitHub Release не выполнялись.

## Найденные реальные маршруты

- Глобальные: `/admin`, `/admin/settings/notifications`.
- Проектные: `/admin/projects/:uuid/brief`, discussions, clients, structure,
  notifications, settings, export.
- Идея: `/admin/projects/:uuid/brief/task/:id`, создание и редактирование.
- Корзина 4.6.1 — существующий диалог с admin API, отдельного frontend route нет.
- Маршрутов команды проекта, личного профиля и безопасности нет. Отдельной
  ветки Milestone 4.7 на GitHub не найдено. Вымышленные ссылки не добавлены.

## Реализация

AdminSidebar выбирает глобальный или проектный режим по текущему route и
проверенному загруженному проекту. ProjectSidebar используется и в левом
сайдбаре, и в правом drawer детальной страницы. ProjectNavigation остаётся
единственным источником проектных ссылок, активного пункта и счётчика обсуждений.
Глобальное меню визуально сохранено. Ссылка «Все проекты» стоит вверху проектного
меню; личные уведомления и выход доступны внизу.

Корзина стоит последней, с разделителем и маленькой иконкой. Её прежний компонент
получил возможность скрыть собственную кнопку, чтобы один диалог обслуживал
сайдбар и drawer. Логика удаления/восстановления и backend API не менялись.
Если корзина открывается с management-страницы без загруженных задач, сначала
загружается текущий проект; контекст повторно проверяется после ожидания.

На главной AdminProjectShell передаёт заголовок ProjectHeader через metadata
projectOverview. Компонент отображает H1 слева и существующие ProjectProgress/
добавление идеи справа. CSS Grid даёт равные колонки без absolute/отрицательных
margin. На mobile колонки становятся вертикальными, а на 320 px прогресс и
добавление идеи также безопасно переносятся. Остальные страницы сохраняют
обычный заголовок без блока прогресса. Горизонтального ProjectNavigation в shell нет.

На ширине <=640 px административный ProjectView показывает native select из
существующего FILTERS и счётчиков. Select и desktop-кнопки связаны с activeFilter.
MediaQueryList change сбрасывает activeSection, поэтому скрытый фильтр не влияет
на результаты после resize. Клиентская фильтрация и клиентская шапка сохранены.
Запрет drag при частичной фильтрации действует через прежний dragEnabled.

Детальная страница сохраняет TaskNavigator, TaskHeaderNavigation, существующий
правый drawer и редактор. Второго постоянного сайдбара нет. Native dialog,
Tab/Escape, aria-current и защита несохранённых изменений сохранены.

stores/adminNavigation предоставляет текущий безопасный UI-контекст. После
отказа API существующий router guard очищает project/task state и удаляет
недоступный проект из списка. Удаление инвалидирует отложенные ответы списка.
Переключение workspace использует прежний процесс clear/bootstrap; серверные
проверки доступа не изменены.

## Проверки

Прошли 200 frontend-тестов и 550 Laravel-тестов (5508 assertions). Основная
браузерная матрица — 32 конфигурации; дополнительно прошли 8 конфигураций
рабочего пространства, 20 корзины/drag, 10 навигации и 4 обсуждений/клиентского
режима. Build, Pint и Prettier прошли.

Точные результаты — verification.json и browser-results.json. Отдельные
регрессионные browser-results JSON лежат в этом же каталоге.

- Frontend-тесты, включая активную проектную навигацию, один H1, один диалог
  корзины, очистку контекста, workspace и отложенные ответы.
- Laravel-регрессия; PHP/backend исходники не менялись.
- Новая браузерная матрица: 1440/1280/768/390/320 × RU/EN × light/dark/system,
  владелец и приглашённый разработчик. Проверены все существующие project routes,
  глобальный список, личные уведомления, счётчики, drawers, длинные названия,
  фильтры при resize, реальные mouse/touch inputs и сохранение порядка,
  восстановление из корзины с management-страницы, workspace и отказ доступа.
- Существующие E2E рабочего пространства идеи: панели, редактирование,
  комментарии, черновики, клиентские режимы.
- Существующие сценарии 4.6.1: drag, пустые/свёрнутые разделы, клавиатура,
  API error/rollback, блокировка повтора, удаление и восстановление.
- Build, Pint, Prettier; production ZIP собирается из чистой копии commit,
  проверяется на секреты, контрольные суммы и через настоящий Laravel HTTP runtime.

UI-матрицы используют изолированные fixtures и настоящий Chromium. Это проверка
реальных действий браузера, а не production-сессии. Production runtime проверяется
отдельно через HTTP на временной БД. Новая система уведомлений не вводилась;
реальная доставка пользователям и аппаратные VoiceOver/TalkBack не проверялись.
