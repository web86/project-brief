# Milestone 4.8.1 — production patch

Применять только поверх Milestone 4.8, commit `6ab3389`. Patch содержит три PHP-файла и изменившиеся frontend assets/index.html. Vendor, migrations, `.env`, БД, storage и пользовательские файлы не включены. Новых зависимостей нет. Push/deployment не выполнялись.

## Обновление

1. Сохраните текущие `app/Http/Controllers/AdminAuthController.php`, `app/Http/Controllers/DeveloperInvitationController.php`, `app/Services/DeveloperInvitations.php` и публичный `index.html`. Желательно сохранить целиком текущие code/public assets. `BASE-CHECKSUMS.txt` содержит ожидаемые SHA-256 заменяемых файлов именно из базового ZIP 4.8; сравните их с серверными файлами до замены.
2. В существующем `~/project-brief-app`: `php artisan down`.
3. Наложите содержимое `private/project-brief-app/` из patch поверх `~/project-brief-app/`; содержимое `public/` — поверх `~/domains/brief.web86.site/`. Загрузите новые файлы assets прежде, чем заменять index.html. Это **добавление/замена отдельных файлов**, не синхронизация с удалением: старые hashed assets пока оставьте для закэшированных страниц и отката.
4. В каталоге Laravel выполните:

```sh
php artisan optimize:clear
php artisan optimize
php artisan up
```

Миграции, Composer/npm, смена APP_KEY, переустановка приложения и обновление vendor не требуются. Если PHP OPcache на Jino не проверяет timestamps, сбросьте OPcache через панель/перезапуск PHP в соответствии с настройками хостинга. ZIP, PATCH.json и инструкции не размещайте в document root.

5. Повторно откройте исходную ссылку из письма в новой вкладке. Уже открытая страница может продолжать использовать прежний JS. Токен хранится только в памяти страницы после удаления URL fragment; после обычного полного reload без исходного fragment ссылку нужно открыть заново из письма.

## Проверка

- RU/EN, light/dark, 320/390 px: только одна пара переключателей в шапке, заголовок и форма возле верха страницы.
- Гость: регистрация доступна сразу, явный выбор «Уже есть аккаунт — войти». Нет публичного поиска существования аккаунтов.
- Новый пользователь: имя, пароль/подтверждение → создание и принятие → назначенные проекты.
- Существующий пользователь, включая аккаунт без memberships и Email с другим регистром: вход → принятие → выбранный workspace и проекты.
- Другой авторизованный аккаунт: оба Email и спокойное уведомление, нет кнопки принятия; «Выйти и продолжить» → вход приглашённым аккаунтом → принятие исходного приглашения.
- Совпадающий аккаунт принимает приглашение сразу. Повторные/просроченные/отозванные ссылки показывают понятное сообщение.
- Неверный пароль не создаёт сессию; прямой POST принятия чужим аккаунтом по-прежнему даёт 403.

SMTP Jino можно проверить вручную прежним способом. E2E 4.8.1 использует реальный Laravel API, database sessions и локальный SMTP-приёмник, не внешнюю доставку.

## Откат

Maintenance → восстановить три сохранённых PHP-файла и предыдущий index.html → очистить/пересобрать Laravel cache → при необходимости сбросить OPcache → проверить вход и клиентский magic link → up. Старые assets сохранены, поэтому старый index.html продолжит загружаться. Новые hashed assets можно удалить позже, когда они больше не используются. БД и memberships patch не изменяет при установке; откат миграций не требуется. Принятые пользователями приглашения и созданные memberships во время эксплуатации сохраняются.

## Сборка

После локального коммита и тестов:

```sh
node deployment/build-invitation-patch.mjs
```

По умолчанию используется исходный ZIP `release/project-brief-20261025-133055-6ab3389.zip`; другой путь задаётся `M481_BASE_ZIP`. Сборщик проверяет базовый commit, разрешённые PHP-изменения, сравнивает assets с базой, проверяет приложение после наложения patch в изолированном runtime и выпускает ZIP с PATCH.json, BASE-CHECKSUMS.txt и checksums.txt. Отдельный `.sha256` позволяет проверить сам ZIP.
