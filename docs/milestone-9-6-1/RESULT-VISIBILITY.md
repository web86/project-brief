# Agent results: factual visibility in v0.9.6 and v0.9.7

The UX patch preserves the existing model. Agent results are **public task comments for authorized project clients**, not internal technical notes. Owner grants constrain what the agent can read/write; they do not limit which existing task participants may read an agent's output.

| Channel                      | Existing behavior                                                                                                                                                                                                                                                                                                     |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Reports and comments         | AgentApiController writes normal comments with `team_only=false`. The client task API and discussion feed include their text and agent attribution.                                                                                                                                                                   |
| Report metadata              | `agentReport` includes state, Pull Request and result URLs for clients. Only the admin-only assignment management field is omitted. Links/text are not classified or redacted according to business sensitivity.                                                                                                      |
| Attachments                  | Normal private storage is used, but authorized clients of the same project can download agent-comment files through authenticated client download routes. Another project or unauthenticated client cannot download them. Private storage is an authorization mechanism, not a promise of team-only content.          |
| Existing private task fields | Developer notes, price and assignment-management fields remain filtered from client task responses and agent input. This does not protect private details that an executor copies into a public report itself.                                                                                                        |
| Email / Telegram / Web Push  | Agent writes do not dispatch `ProjectNotificationRequested`; the regular delivery pipeline is not automatically started by these operations. This is not a guarantee that all notification channels can never show agent content.                                                                                     |
| Live notifications           | With the normal ProjectNotificationSetting row, no `agent.comment_created` rule exists, so the current live notification filter omits these previews. If that settings row is absent and recipient push preferences allow notifications, the fallback permits a comment preview. The client can receive that preview. |
| Unread discussions / refresh | Public agent comments are ordinary discussion activity and can appear in unread counts and refreshed task/discussion data independently of notification delivery.                                                                                                                                                     |

Regression tests assert same-project reading, result URL visibility and downloads, denied foreign-project access, private field filtering, no normal notification event, and both live-notification settings cases. No real SMTP/Telegram/Web Push delivery was performed. No claims about live production data are made.

**Practical consequence:** technical descriptions, internal URLs or secrets placed in agent output can be disclosed to a client with task access. URL validation prevents unsafe schemes/embedded URL credentials, but does not determine whether a legitimate HTTPS URL is confidential. The task UI now states that agent reports may be visible to clients.

## Minimal future model, proposed only

Add an explicit audience for **new** comments/reports, using the existing team-only comment boundary where possible. Default new technical agent output to internal only after an explicit product decision and API version/compatibility plan; require an authorized human action to publish a client-facing copy. Apply the same audience filter to task/discussion resources, attachment download/preview authorization, live updates, unread counts and every notification payload. Test workspace/project isolation and retained authorship/audit.

Existing comments must retain their current audience. Any reclassification needs a separate reviewed operation and clear impact reporting; no hidden migration, retroactive hiding or API behavior change is included in v0.9.7.
