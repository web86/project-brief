# Milestone 4.6.1 — отчёт

Реализованы drag-and-drop и настоящая корзина. Основа `1e3622f`, ветка
`codex/milestone-4-6-1-task-management`. Исходные локальные изменения в README.md,
package.json, .gitignore и существующих preview/docs не включены в реализацию.

## Порядок идей

TaskCard, SectionBlock и ProjectView используют Pointer Events с отдельной ручкой
только у разработчика. Карточка остаётся ссылкой, ручка находится вне неё. Начало
жеста требует движения на 10 px; touch-action:none применяется только к ручке.
Страница прокручивается обычным образом за остальную карточку. Есть Escape,
pointercancel, обработка потери фокуса, автопрокрутка у границ экрана и защита от
клика после drag. При фильтре статуса или раздела ручки отключены с пояснением.

Положение вставки подсвечивается без перестройки сетки во время drag. Копия
карточки движется над сеткой с тенью; перестановка внутри раздела анимируется
TransitionGroup и учитывает prefers-reduced-motion. Для клавиатуры кнопка ручки
открывает доступный native dialog с командами выше/ниже и выбором раздела/позиции.
На детальную страницу управление порядком не возвращено.

Новый POST `/api/admin/tasks/{task}/place` принимает sectionId и один из
beforeTaskId/afterTaskId; без якоря добавляет в конец. Одна транзакция блокирует
проект, повторно читает задачу, проверяет проект раздела и актуальность якоря,
пересчитывает позиции и пишет историю. `/move` и `/reorder` сохранены. Ответ
содержит текущий список проекта, поэтому клиент обновляет весь порядок одним
запросом. При ошибке исходные позиции восстанавливаются. Черновики разработчика
хранятся отдельно и не теряются. В другой сессии порядок виден после загрузки.

## Корзина

Task использует Eloquent SoftDeletes. Новая nullable deleted_at не меняет
существующие записи. DELETE доступен клиенту и администратору, только для
несогласованного new, с повторной проверкой под блокировкой проекта/задачи.
ClientTaskDeletion больше не копирует и не удаляет физические файлы.

Кнопка внизу после комментариев присутствует у обоих участников, остаётся
неактивной для других статусов и clientApproved. Диалог объясняет восстановление,
не закрывается при выполнении запроса, блокирует повторное подтверждение,
при ошибке оставляет страницу, при успехе возвращает к списку с уведомлением.
Клиентское редактирование clarification сохранено; удаление clarification запрещено.

GET `/api/admin/projects/{project}/trash` и POST `/api/admin/tasks/{task}/restore`
проверяют доступ к проекту. Восстановление под той же блокировкой вставляет на
сохранённую позицию (или конец, если раздел сократился), нормализует порядок и
сохраняет историю. Разделы с идеями в корзине защищены от удаления.

SoftDeletes исключает идеи из ORM-запросов, экспорта, доступов к файлам,
обсуждений, обычных счётчиков и уведомлений. SQL-выборка ProjectUnread отдельно
исключает tasks.deleted_at. Содержимое, вложения, комментарии и история сохранены.
Полноценная корзина реализована; безвозвратного удаления нет.

## Проверки и доказательства

Итог: 197 frontend-тестов; 550 Laravel-тестов / 5508 assertions на PHP 8.5.10
и на целевом PHP 8.4.26; 20 браузерных конфигураций; 4 конкурентных сценария
MariaDB. Все перечисленные проверки прошли.

- Frontend: `npm test`, включая тесты переноса, сохранения, rollback, корзины,
  восстановления, условий доступа и повторного подтверждения.
- Laravel: `PHP_INI_SCAN_DIR=:$PWD/dev-php php artisan test --compact` в api.
  Feature-покрытие всех шести статусов × clientApproved × двух участников,
  повторных запросов, чужих проектов, сохранности связанных данных/файлов,
  прямого доступа, экспорта, счётчиков и восстановления.
- Браузер: `tests/task-management.browser.mjs`. Реальные Chromium mouse inputs
  и touch через CDP, клавиатура Enter/select, сохранение/reload, отказ API,
  блокировка повторного переноса, пустой/свёрнутый раздел, длинные названия,
  фильтры, удаление/отмена/ошибка/восстановление, отсутствие ручек у клиента.
  API для этой UI-матрицы — изолированные fixtures, PHP проверен отдельно и
  дополнительно через HTTP в упакованном runtime. Это не production-сессии.
- Конкурентность: `tests/task-management.concurrent.mjs` и PHP worker,
  четыре настоящих параллельных сценария на отдельной MariaDB 11.8.9.
  Проверены две разные идеи, одна идея, переехавший якорь (409), согласование,
  завершившееся пока удаление ждёт row lock (403). Позиции остаются непрерывными.
  Результаты — concurrency-results.json; контейнер после проверки удалён.
- `VITE_DATA_SOURCE=api VITE_API_BASE_URL= npm run build`, Pint, Prettier.
- Сборщик проверяет чистый source snapshot, production vendor, отсутствие
  секретов, SHA-256, миграции и HTTP/runtime упакованного приложения.

Числа и артефакты финального прогона — в verification.json,
browser-results.json, concurrency-results.json и build-report.json рядом с ZIP.

## Практические пределы

Чужая вкладка не обновляется автоматически: нужен reload. Клавиатурная альтернатива
реализована диалогом выбора позиции. Отправка Email/Push/Telegram покрыта
существующими регрессионными тестами с изолированными транспортами; реальная
доставка и аппаратные VoiceOver/TalkBack на пользовательских устройствах не
проверялись. Production smoke выполняет оператор по PRODUCTION.md.

Push, deployment и GitHub Release не выполнялись. Deno-мост и реализация
Telegram webhook не изменены.
