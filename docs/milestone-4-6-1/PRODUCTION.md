# Project Brief 0.4.6.1 — инструкция обновления

Обновление с Milestone 4.6 (`1e3622f`). Ветка: `codex/milestone-4-6-1-task-management`.
Полный ZIP содержит Laravel, production vendor, готовые Vue assets и миграции.
Новых env-переменных и frontend-зависимостей нет. Целевой production PHP — 8.4.
Обновление выполняет оператор; deployment агентом не выполнялся.

## Перед обновлением

Сохраните резервную копию БД, текущего приложения, public assets, приватной `.env`
и всего `storage/`, включая uploads, сессии и историю доставок. Сохраните APP_KEY,
SMTP, VAPID, Telegram secrets и действующие параметры домена/HTTPS.

Deno-мост и Telegram webhook не меняются. Файл `deployment/telegram-bridge.mjs`
в ZIP включён для справки и совпадает с базовым commit. Не выполняйте повторный
деплой моста, setWebhook, deleteWebhook или сброс pending updates.

## Установка

В действующем `~/project-brief-app` включите maintenance:

```sh
php artisan down
```

Загрузите файлы из архива по существующей схеме Jino:

```text
private/project-brief-app/ → ~/project-brief-app/
public/                   → ~/domains/brief.web86.site/
```

Замените vendor целиком. Сохраните действующие `.env`, APP_KEY и содержимое
storage; не заменяйте их пустыми каталогами архива. Учтите скрытые public files.
Удалите старые скомпилированные файлы из `bootstrap/cache`, сохранив каталог,
права и maintenance marker. ZIP, private, исходники моста и инструкции должны
находиться вне document root. Общие требования — в DEPLOY-JINO.md.

В `~/project-brief-app` выполните:

```sh
php artisan config:clear
php artisan migrate --force
php artisan optimize
php artisan up
```

При ошибке migration/optimize оставьте maintenance до устранения причины.
Не выполняйте first-install, key:generate, migrate:fresh, db:wipe или seed.
Composer, Node и npm на production не требуются.

## Изменение схемы и данных

Новая миграция `2026_10_25_074255_add_deleted_at_to_tasks_table.php` добавляет
nullable `tasks.deleted_at` и индекс `(project_id, deleted_at)`. Существующие
поля и данные не переписываются; у всех прежних идей `deleted_at = NULL`.

Удаление разрешено обоим участникам только при `status = new` и отсутствии
client approval. Проверка повторяется под блокировкой непосредственно при
удалении. Согласованная идея со статусом new остаётся защищённой.

Корзина сохраняет файлы, комментарии, историю, проект, раздел и прежнюю позицию.
Администратор открывает её из списка идей проекта. Восстановление вставляет
идею в прежнюю позицию, ограниченную текущей длиной раздела, и пересчитывает
номера. Раздел с идеями в корзине нельзя удалить: сначала восстановите идеи
и перенесите их. Безвозвратного удаления и физической очистки файлов нет.

Идеи из корзины исключены из рабочих списков, экспорта, обсуждений, счётчиков,
прямых ссылок и новых доставок уведомлений. Уже отправленные ранее сообщения
каналов не отзываются.

## Проверка после обновления

1. Обновите вкладки браузера. Проверьте `/api/health`, вход разработчика и
   действующую клиентскую ссылку.
2. На тестовой несогласованной новой идее проверьте перенос мышью за ручку,
   перенос в пустой/свёрнутый раздел, точную вставку и повторную загрузку.
   Для клавиатуры нажмите Enter на ручке и выберите раздел/позицию.
3. Проверьте touch на телефоне/планшете. Обычная прокрутка карточки не должна
   менять порядок. При фильтрах перемещение отключено; сбросьте оба фильтра.
4. Откройте две административные сессии. Параллельные операции сохраняют
   последовательные позиции; если целевая идея уже переехала, повторите после
   обновления страницы. Автоматического live-обновления чужой вкладки нет.
5. Проверьте кнопку удаления внизу страницы клиента и разработчика, отмену,
   ошибку, успех и восстановление через корзину разработчика. Проверьте
   комментарии, историю и скачивание сохранённого файла после восстановления.
6. У согласованной новой идеи и всех других статусов удаление недоступно.
   Проверьте клиентский список, номера, экспорт и отсутствие удалённой идеи
   по прямой клиентской ссылке.
7. Проверьте RU/EN, светлую/тёмную/системную тему, черновики, client approval.
8. Используйте существующие тестовые действия Email/Push/Telegram и одну
   контролируемую операцию на тестовой идее. Реальную доставку на production
   проверяет оператор; локальные тесты не отправляли сообщения пользователям.

## Откат

Сохраните новый архив и резервную копию до обновления. При необходимости
восстановите согласованную резервную копию кода, assets и БД в maintenance.
Не откатывайте только код на 4.6 после использования корзины: старая версия
не учитывает deleted_at и покажет скрытые идеи. Не удаляйте колонку deleted_at
и не запускайте down-миграцию для обычного отката: это потеряет отметки корзины.
Вложения не удаляются и должны сохраняться при любом откате.
