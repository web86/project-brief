# Project Brief 0.8.4 — UX Polish & Live Notifications

База: `codex/fix-sso-source-projects`, commit `2d909d7`. Рабочая ветка: `codex/milestone-8-4-ux-live-notifications`.

Восстановление пароля доступно только пользователям с действующим членством владельца или разработчика. Клиентские email и неизвестные адреса получают тот же нейтральный ответ, без письма и reset-токена. Существующие лимиты запросов и одноразовый Laravel Password Broker сохранены. Регистр email учитывается без различения.

Новый внутренний POST `/api/admin/password/inspect` проверяет email, роль, срок и hash reset-токена, затем возвращает только необходимость TOTP. Недействительная ссылка не раскрывает состояние второго фактора. После проверки форма содержит пароль/подтверждение и, при необходимости, одно поле Authenticator или резервного кода с переключением. Резервные коды проверяются и расходуются сервером под блокировкой пользователя. После успеха форма исчезает, секреты очищаются и через 1,5 секунды открывается вход; ссылка позволяет перейти сразу. Ошибка сохраняет введённый пароль в текущем компоненте. Дублирующие переключатели темы/языка удалены со страницы — остаётся общая шапка.

В интеграциях сначала показаны списки, затем раскрываемые формы создания API-ключа/Webhook. Пустой список сразу открывает форму. Создание обновляет список; сворачивание происходит после закрытия диалога одноразового секрета. Черновик сохраняется при ручном сворачивании. Настройки SSO перенесены в свою вкладку; их backend и права не изменены. Информационный пример режима приглашения удалён из интерфейса, а сам `sendInvitation` продолжает работать. Строки последних операций компактнее, длинные значения переносятся на мобильном экране.

Новые задачи, комментарии и статусы появляются через существующий toast-компонент. Уведомления содержат краткий контекст и ведут к проекту/задаче/комментарию. Имена и текст выводятся как текст, без HTML; длина ограничена. Свои действия исключаются, появление toast не отмечает событие прочитанным. На экране одновременно не более двух подробных событий и одного сводного уведомления. Смена пользователя/workspace очищает превью.

Live Sync читает существующие `task_history` и `comments`; новые notification-записи и отдельный polling не добавлены. Учитываются текущие права на проект, активность клиента/проекта, личный browser/push-переключатель, правила и выбранные получатели проекта. Для статусов без отдельного исходящего события используется совокупность разрешённых browser-правил получателя. Email, Telegram, Web Push, webhook outbox и cron не менялись.

Существующий координируемый опрос выполняется раз в 60 секунд вместо 300. Скрытая вкладка не запрашивает данные и не показывает toast. Ошибки увеличивают паузу до пяти минут; сигналы Web Push не обходят backoff. Web Locks, BroadcastChannel и общий timestamp сокращают повторные запросы вкладок. Превью не передаются через BroadcastChannel и не сохраняются в localStorage: там только ограниченные ID квитанций и время проверки. Начальная загрузка задаёт курсор без старой пачки; курсоры старше десяти минут получают новый baseline для toast. Короткое перекрытие чтения компенсирует обычную задержку commit; ID-квитанции исключают повторный показ.

RU / EN / TR / ZH-CN, desktop/mobile и Light/Dark сохранены. Новых таблиц, миграций, зависимостей, WebSocket, Redis, cron или очередей нет.
