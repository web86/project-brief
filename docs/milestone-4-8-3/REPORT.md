# Milestone 4.8.3 — Client Notifications Autosave & Discussions Tabs

Ветка `codex/milestone-4-8-3`, база `main` / `be2b883f99ef35bbe61bc2113bece51a543b6822`. Изменения 4.8–4.8.2, проектные полномочия и персональные уведомления сохранены. Push и deployment не выполнялись.

## Персональные уведомления клиента

Кнопка обязательного сохранения и внешняя форма удалены. Каждый переключатель Email/Push/Telegram сохраняет предпочтение через прежний `PATCH /api/client/notifications`. Backend и контракт персональных уведомлений не изменены.

Общий `personalNotifications.savePreference()` используется клиентом и администратором. Одна очередь для текущей identity отправляет не более одного PATCH одновременно. Разные каналы можно быстро изменить: следующая запись строится из последнего подтверждённого ответа сервера, а не из устаревшей копии всех настроек. Канал с ожидающим сохранением временно заблокирован; повторные события не отправляют дублирующий запрос. Отказ одного запроса не теряет последующие изменения других каналов.

Переключатель остаётся в подтверждённом состоянии до ответа; при ошибке сохраняется прежнее значение и выводится локализованная ошибка. При успехе принимается весь ответ сервера. Смена пользователя/типа доступа сбрасывает очередь и не позволяет старому ответу или ещё не отправленному запросу затронуть новую identity, включая A → B → A. Выход со страницы в пределах той же сессии не отменяет уже подтверждённое пользователем намерение сохранить настройки.

Telegram preference и подключение Telegram — разные операции. Переключатель вызывает только notifications PATCH; connect/reconnect/disconnect/test остаются в TelegramSettings. Дизайн карточек, состояния каналов, Push controls и RU/EN сохранены. У администратора переиспользована общая функция записи с прежней блокировкой административных действий.

## Обсуждения

Две вкладки: «Общие комментарии» (по умолчанию) и «Последние комментарии». Старый All/Unread переключатель удалён из UI. Общая форма комментария сохранена; скрытие панели через v-show и существующие drafts не теряют введённый текст. Одновременно видна только одна лента. Переключение локальное, не загружает данные заново и ничего не отмечает прочитанным. Для каждой ленты сохраняются свой cursor и загруженные страницы; повторное нажатие пагинации объединяется с ожидающим запросом.

Вкладки используют tablist/tab/tabpanel, aria-selected/controls/labelledby, roving tabindex, ArrowLeft/ArrowRight/Home/End и focus-visible. На мобильном обе вкладки занимают одну строку с равной шириной, допускают двухстрочные названия и сохраняют место для бейджа.

GET обсуждений и POST read дополнены `unreadCounts: { general, tasks }`; прежний `unreadCount` сохранён. Агрегат вычисляется сервером по всем видимым непрочитанным комментариям, независимо от фильтра, cursor или страницы. POST read принимает необязательный `kind`: `{ all: true, kind: 'general' }` отмечает только общие комментарии. Запрос без kind сохраняет прежнюю семантику всех категорий. Индивидуальные IDs проверяются на принадлежность проекту и, если указана, категории. Общий бейдж меню обновляется из того же ответа API; clientNavigation использует уже существующий `project.unreadCommentCount` и отдельной логики не требует.

Для `#comment-ID` сначала проверяются загруженные комментарии. Если целевого сообщения нет, `GET .../discussions?comment=UUID` возвращает его категорию и хронологическое окно из 25 сообщений, начиная с него, с обычным cursor к более старым сообщениям. Вкладка выбирается автоматически, сообщение получает фокус и прокрутку. Кнопка «Показать последние сообщения» возвращает начало ленты. Чтение при этом не отмечается. Недоступный/удалённый комментарий показывает понятное сообщение. Сортировка created_at DESC, id DESC сохранена.

Identity/project revisions, очередь read и версии прочтений защищают от смешивания пользователей/проектов и возврата устаревших счётчиков после read. Более ранний target-запрос не перезаписывает более позднюю ссылку в том же проекте. ProjectAccess, клиентские сессии, видимость комментариев, CSRF и права владельца/назначенного разработчика не менялись. Приватные поля задач не добавлялись в клиентский API.

- Полный Laravel-набор: **593/593**, 6107 assertions, SQLite. Новые сценарии охватывают owner/developer/client, категории за пределами первой страницы, mark-one/mark-tab/legacy-mark-all, собственные сообщения, cursor, старые target-сообщения, чужие/удалённые комментарии и валидацию параметров.
- Связанные Laravel-тесты на MariaDB 11.8: **20/20**, 464 assertions.
- Полный frontend-набор: **232/232**. Добавлены проверки сериализации/дедупликации, отказа и последующего сохранения, серверного ответа, смены аккаунта, счётчиков, пагинации/read race, target race, drafts и семантики обеих локализаций.
- Реальный browser E2E обсуждений: **24** комбинации owner/developer/client × 1440/390px × RU/EN × light/dark; база содержит по 70 непрочитанных сообщений каждой категории при странице из 25. Проверены независимые бейджи, индивидуальное/массовое чтение, меню, сохранение draft, отправка, пагинация двух лент, ссылки вне первой страницы, фокус, клавиатура, смена проекта и отсутствие горизонтального overflow. Получены **48** скриншотов, JS-ошибок нет.
- Browser E2E уведомлений/навигации: **36** сценариев, включая ошибки и возврат значения, быстрые три канала, отсутствие дубликатов, reload и отдельную процедуру Telegram connect.
- Актуальный Milestone 4.6 quick: проверка прежних проектных/личных уведомлений и смены workspace. Исторический Milestone 4.5 browser harness содержит ожидания прежнего проектного Telegram-экрана; он не используется как приёмка текущего интерфейса. Актуальные маршруты проверены двумя указанными browser-наборами и 4.6 quick.
- Build, Prettier, Pint и git diff --check. Patch builder отдельно проверяет базовый коммит, allowlist PHP-файлов, secrets, целостность ZIP и runtime объединённой production-поставки.

Точные результаты: [QA.json](QA.json), [real Laravel browser-results.json](browser-results.json). Мобильные сценарии выполнены в Chromium с touch-эмуляцией; физический телефон и Safari не использовались. Внешняя доставка Email/Push/Telegram не выполнялась.
