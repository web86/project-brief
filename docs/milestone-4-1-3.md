# Milestone 4.1.3 — Groq через Deno Deploy

## Результат

Добавлен провайдер `groq_bridge` в существующий Laravel `AiTaskAssistant`.
Один авторизованный live-запрос с синтетическим ТЗ завершился **HTTP 200**;
Groq `openai/gpt-oss-120b` принял текущую строгую JSON Schema. Ответ прошёл тот же
Laravel-валидатор, что используется формой задачи. Время HTTP-запроса из Laravel
составило **1614.9 мс**. Повторов, смены провайдера и дополнительных live-запросов нет.

Подтверждённая цепочка: локальный Laravel → существующий Deno Deploy Bridge → Groq.
Проверка с Jino не выполнялась. Один успешный запрос не доказывает отсутствие лимитов
во всех регионах/аккаунтах: он подтверждает доступность данного аккаунта/развёртывания
в момент проверки. В данном вызове отказов 403 или иных признаков запрета доступа нет.
Механизмов автоматического обхода ограничений не добавлено.

## Проверенная реализация моста

Изучен [main.js](https://github.com/web86/projectbrief-ai-bridge/blob/main/main.js),
blob SHA `3e233bfae4db771746d91d7cb5efa999eb0dbd65`.
Laravel отправляет запрос только на
`https://projectbrief-ai-bridge.web86.deno.net/ai`.

Контракт прочитанного исходника:

- Авторизация Laravel → Deno: `Authorization: Bearer <AI_BRIDGE_SECRET>`;
  секрет должен иметь не менее 32 символов.
- Deno использует свой `GROQ_API_KEY` для Groq; Laravel не передаёт этот ключ мосту.
- Разрешены только `openai/gpt-oss-120b`, нестриминговый Chat Completions payload
  и `response_format.type=json_schema` с `strict=true`.
- Максимальный размер входа моста — 100000 байт, upstream timeout — 20 секунд.
- Ошибки Groq 429 возвращаются как bridge HTTP 429; остальные upstream HTTP-ошибки,
  включая 403, возвращаются как HTTP 502 с числовым `providerStatus`.
- Необходимые секреты не настроены → 503; неверный bridge secret → 401;
  upstream timeout/network error → 504. Содержимое upstream ошибок не раскрывается.

Исходники Deno Bridge и его deployment не менялись.

## Изменения Laravel

`groq_bridge` использует **тот же JSON payload**, что прямой `groq`: system prompt,
пять выбранных полей формы в user message, модель, JSON Schema, `strict=true`,
`stream=false`, `max_completion_tokens=6000`, `reasoning_effort=low`.
Feature-тест сравнивает два реальных исходящих fake-запроса целиком по JSON body.

Изменились URL и Bearer-secret транспортного запроса. `AI_BRIDGE_URL` хранится только
в backend config и проверяется по точному разрешённому адресу этого моста. Адреса
других хостов/путей, HTTP, query и userinfo отклоняются до отправки и расходования
workspace-квоты. Это не универсальный HTTP-прокси; смена развёртывания требует
обновления разрешённого адреса в коде.

Прямые `groq`, `zveno` и явный `ZVENO_OUTPUT_MODE=prompt_json` сохранены.
Валидация входа и ответа, whitelist полей, ограничения длины/списков,
project/workspace middleware, общие квоты, запрет логирования текста/ключей и
механизм ручного применения не менялись. Frontend и интерфейс не редактировались.
Генерация ничего не сохраняет в задачах или истории.

Bridge HTTP 401 возвращается пользователю приложения как безопасный 503:
ошибка backend-секрета не завершает пользовательскую сессию. HTTP 429 сохраняет
прежнюю обработку лимита. Bridge HTTP 504 возвращает `504 / ai_timeout`.
HTTP 502/503 и upstream запрет 403 возвращают `503 / ai_unavailable`, без сырых
сообщений и дополнительных попыток. Синтетическая CLI-проверка сохраняет только
безопасный bridge error code и числовой `providerStatus` для диагностики.

## Настройка

Только `api/.env`:

```dotenv
AI_ENABLED=true
AI_PROVIDER=groq_bridge
AI_BRIDGE_URL=https://projectbrief-ai-bridge.web86.deno.net/ai
AI_BRIDGE_SECRET=your-server-side-bridge-secret
GROQ_MODEL=openai/gpt-oss-120b
```

Текущий локальный backend настроен на этот провайдер после успешной проверки.
Файл `.env` игнорируется Git, права 0600; реальные значения секретов в коммит не
попадают. В `.env.example` и `.env.production.example` секрет пустой, а провайдер
по умолчанию остаётся `groq`. На Deno уже настроены его `AI_BRIDGE_SECRET` и
`GROQ_API_KEY`; в этой задаче эти настройки не менялись.

Если backend config закэширован, после его изменения выполните в `api`
`php artisan config:clear`. Без bridge secret, при секрете короче 32 символов
или неизвестном URL исходящий запрос не выполняется.

План без сети: `php artisan ai:bridge-check`.
Для будущей отдельно авторизованной одиночной проверки:

```sh
php artisan ai:bridge-check --live --output=/tmp/groq-bridge-check.json
```

Существующий report-файл не перезаписывается. Команда не читает клиентские задачи,
не отправляет запросов при простом запуске без `--live` и не повторяет запрос при
любой ошибке. Если bridge либо upstream отвечает 403, команда сообщает об отказе
доступа и останавливается; региональные альтернативы не пробуются.

## Тайм-ауты и ограничения

Рекомендуется сохранить текущие значения:

- Deno → Groq: **20 секунд** по изученному исходнику моста.
- Laravel HTTP Client: **25 секунд**, connect timeout **5 секунд**.
- Frontend AI request: **35 секунд**.

Такой порядок оставляет Laravel время получить контролируемую ошибку Deno и
передать её frontend. При единственном измерении 1.615 секунды оснований увеличивать
тайм-ауты нет. Это не p95/p99 или нагрузочный benchmark. Для Jino отдельно проверьте
общий PHP/FastCGI/web request budget: желательно не менее 30 секунд с учётом
накладных расходов; frontend уже ожидает до 35 секунд. Реальные серверные лимиты
Jino в этой задаче не измерены и не изменены.

Ограничение моста 100000 байт может отклонить особо длинный payload, даже если
каждое поле укладывается в индивидуальные лимиты Laravel; бизнес-ограничения формы
ради моста не сокращались. Bridge работает синхронно; новых очередей, серверов
или фоновых процессов приложения не создавалось.
