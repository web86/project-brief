# Project Brief

Локальный MVP для обсуждения изменений сайта между клиентом и разработчиком.
Клиент описывает идею своими словами, а разработчик получает список работ по разделам сайта.

## Запуск

Нужен Node.js 20.19+ или 22.12+ (проверено на 22.23.2).

```bash
npm install
npm run dev
```

Откройте http://127.0.0.1:5173. Порт закреплён, чтобы адрес хранилища не менялся между запусками.
Если он занят, остановите предыдущий сервер этого проекта.

```bash
npm run build        # сборка в dist/
npm run preview      # просмотр собранного приложения
npm test             # тесты store, сохранения и обработки вложений
npm run format:check # проверка форматирования
```

## Возможности

- Девять демо-идей при первом запуске, все шесть статусов, несколько обсуждений.
- Главный экран: компактный прогресс, группировка по месту на сайте и фильтры. На desktop от 1200 px — три колонки, от 700 до 1199 px — две, ниже — одна.
- Простая форма идеи: название, место на сайте и описание. Результат, важность и вложения визуально вторичны.
- «Где это находится?» — свободное поле с подсказками существующих мест: можно выбрать раздел, написать своё название или вставить полную ссылку. Подсказки доступны мышью и клавишами ↑/↓, Enter, Escape; Tab переходит дальше.
- JPG, JPEG, PNG, WEBP, PDF, DOC, DOCX, TXT, ZIP; до 10 файлов на идею, до 20 МБ каждый.
- Для изображений сохраняются уменьшенные превью до 1000 px и 180 КБ. Для остальных файлов сохраняются только название, тип и размер. Оригиналы файлов не сохраняются и не отправляются.
- Скриншот можно вставить через Ctrl+V / Cmd+V на странице новой идеи. Он проходит ту же проверку и подготовку превью, что выбранный файл. Вставка обычного текста работает как прежде.
- Страница идеи: описание, результат, превью и комментарии рядом на desktop. Согласование показывается компактно, история изменений по умолчанию свёрнута.
- Переключатель режима без авторизации. В режиме разработчика доступны статус, часы, стоимость в рублях и технические заметки.
- Все изменения и выбранный режим автоматически сохраняются в localStorage. Поля разработчика сохраняются при вводе; последовательный ввод объединяется в одно событие истории.
- Согласование клиента хранится отдельно от статуса, установленного разработчиком.
- AI-кнопка открывает демонстрационное окно. Сервис имеет точку подключения будущего API и основу для нескольких предложенных идей.
- Мобильная вёрстка, подписанные поля, клавиатурная навигация, модальные окна с управлением фокусом, пустые состояния и страница 404.

## Архитектура и файлы

```text
src/
  assets/main.css           # vanilla CSS, адаптация и стили
  components/               # карточки, форма, файлы, обсуждение, история, панели
  constants/project.js      # единые статусы, важность, фильтры и форматирование
  data/demo.js              # начальный демонстрационный проект
  router/index.js           # /, /task/new, /task/:id и 404
  services/ideaAssistant.js # демонстрационный адаптер будущего AI
  stores/project.js         # Pinia store, действия и сохранение
  utils/attachments.js      # проверка файлов и подготовка превью
  views/                    # ProjectView, TaskFormView, TaskView, NotFoundView
  App.vue                   # оболочка, переключатель режима, ошибки хранилища
  main.js                   # Vue 3, Pinia и Vue Router
tests/project.test.js       # тесты жизненного цикла проекта
tests/attachments.test.js   # вставка изображений и ограничения файлов
docs/verification.md        # первоначальная проверка MVP
docs/ux-cleanup.md          # проверка текущего интерфейса и скриншоты
```

Vue 3 Composition API, Vite, Pinia, Vue Router, без UI-фреймворков.
Store содержит все действия из задания: addTask, updateTask, deleteTask,
changeStatus, approveTask, addComment, updateDeveloperData, loadFromStorage,
saveToStorage. Обновление и удаление доступны как действия store; отдельный интерфейс редактирования и удаления не добавлен в этот MVP.

## Хранение данных

Ключ: `project-brief:v1`, версия схемы: 1.
Снимок содержит project, sections, tasks и currentMode. Изменения отслеживаются глубоким watcher.
Место задачи читается через `task.location || task.section`: прежние задачи не требуют миграции.
Новые идеи записывают `location` и совместимый `section`; произвольные значения участвуют
в группировке и подсказках. URL хранится полностью, сокращается только отображение через CSS.
Перед восстановлением проверяется вся структура. Некорректное сохранение остаётся нетронутым,
показывается предупреждение, запись блокируется. При переполнении памяти изменения остаются
в состоянии текущей страницы; интерфейс показывает ошибку и кнопку повторного сохранения.

Данные существуют только в текущем браузере и привязаны к адресу (схема, домен, порт).
`localhost`, `127.0.0.1` и адрес preview имеют разные хранилища.
Режимы служат демонстрацией интерфейса: без backend клиент и разработчик не могут совместно
работать с одной копией данных на разных устройствах. Режим разработчика не является защитой доступа.
